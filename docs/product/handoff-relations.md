# 交接文档：用“关系”重新理顺隐私与支付（2026-10-18）

给新开的两个对话框使用：一个讨论**隐私**，一个讨论**支付**。读完本文件即可接上，不需要翻之前的聊天记录。

## 一、这个产品是什么

- 名字：知衡（仓库 Aster-Ai）。一个**治未病**社区：一两位老师带若干学生，智能体做老师时间的放大器。
- 最根本的几句话（发起人定）：
  - 治未病；“中医”的“中”是中庸的中，根本是**平衡**。
  - 心理健康决定生理健康；多数疾病和坏习惯根子是压力。
  - 难的不是治，是**坚持**；老师的方案和动作一人一套，对这个人有效，换一个人就未必。
  - 以老师为中心；用户看得见的一律从简；多出来的步骤由学生做。
- 用户：主力是 40 岁以下的年轻老师和学生；最需要的是 40～50 岁“上有老下有小”的人（替老人孩子开家人账户）。多数在国内，链接靠微信传。

## 二、现状

- 第一版代码已**封存**在分支 `archive/v1-frozen`。功能都在：手机网页应用、问诊、老师起草签字、作业打卡、镜子页、康币账本、家人账户、自带模型、家用电脑部署。
- 封存原因：**还是太复杂**，尤其隐私和加密考虑得过多。下一版先拆结构、理顺关系，再施工。
- 产品依据：`docs/product/two-agents.md`；决策记录：`team/decisions.md`。

## 三、关系是一切的基础（发起人 2026-10-18）

- 人与自然、人与自我（吃、睡、想），《黄帝内经》已经讲明白；平台的作用是把高手看透的简单道理，注入不明白的人身上。
- **人与人只有两种关系：**
  1. **教学关系（师生）**：没有交易。黄帝与岐伯之间不谈钱。**治未病是师生关系。**
  2. **交易关系**：有交易。**治已病是交易关系**，就像去名校上学要交学费。
- 产品里叫“老师 / 学生”，不是为了合规，而是治未病本来就是师生关系。

## 四、第一版里与这两种关系相关的做法（供推倒重来时参考）

- **隐私（第一版做得重）**：端到端加密消息（Nostr 礼物包裹）、数据只在手机上、诊毕即还（老师签字后删除原始资料）、所有本地数据加密、界面隐藏密钥、代管证明签名等。
- **支付（第一版只做了账）**：康币 = 每位老师一本账，学生在社区外付钱，老师记充值、赠送、扣费、退款；学生 7 天内可提异议；一家一本账；社区不经手钱。未来设想过比特币/智能合约。

## 五、发起人的初步看法

- **隐私**：一个人的方案和动作只对他本人有效，被谁看去都没用（“你不是我，你不知道为什么”）；中医的阴阳五行本身就是最好的“加密”；中国人对医生不讲隐私。所以没必要对健康数据做复杂加密。
- **支付**：还没想明白。

## 六、两个对话框各要回答的问题

**隐私对话框**
1. 在教学关系（治未病）里，哪些东西需要保护，哪些根本不需要？
2. 去掉加密以后，第一版里哪些模块可以整个删掉？（例如礼物包裹、本地加密、诊毕即还、密钥派生……）
3. 哪些东西即使简化也要留？（技术合伙人按约定**只提一次**，由发起人拍板。）

**支付对话框**
1. 教学关系里要不要有钱？如果有，它是什么性质（供养、赠予、学费）？
2. 交易关系（治已病：开方、药材、面诊）里，钱怎么走、谁记账、要不要平台参与？
3. 康币还要不要？一本账还要不要？
4. 两种关系在产品里是不是两条完全分开的路？
