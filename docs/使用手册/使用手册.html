第一部分

一、知衡是什么

知衡把您的“馆”搬到学生的手机上。学生每天在家照镜子、按您给的方案坚持；不舒服时，把情况整理好发给您。您看过、改过、亲手签字，再交还给学生。

它不是一个大平台，也不是网店。每位老师有自己的馆，名字、颜色、介绍都由您定；学生看到的是“您的馆”，不是别人的。

每个人（老师和学生）手机上都有一个自己的小助手，也就是“智能体”。学生的助手陪学生看自己、记自己、坚持下去；您的助手替您起草病历、整理账目、打理门面。助手只起草，决定永远是您做。

二、能帮您解决什么问题

平时的难处知衡怎么帮
学生知道该怎么做，就是坚持不下来作业挂在学生已有的习惯上（比如“刷完牙按揉太渊穴”），到点提醒，打卡后看得到连续几天。
学生远程描述不清，问一句答一句学生的助手按您的问诊模板先追问一遍，把“哪里不舒服、多久了、吃过什么药”整理成一张卡片，学生核对后才发给您。
照片看不清，或者拍进了半张脸舌象照片当场处理：只留舌头那一块，加一张示意图和候选特征，看不准的标“不确定”。原图不保存、不发送。
写病历、开作业占时间您的助手先起一份草稿，您改哪里都行，确认后亲手签字发出。草稿学得越来越像您。
收费、记账琐碎学生在社区外付给您钱后，您对助手说一句“收到小王 100，送 20”，核对后确认入账；学生在自己手机上看得到余额。
一家老小都要照顾家里的管理人可以替父母、孩子开子账户，代他们问诊；一家一本账。

三、您的馆长什么样

同一套系统，换一份设置，就是不同的馆。下面是两个示例：一位养生老师、一位运动老师。

您可以自己改：馆名、称呼、小标志、配色、一段短介绍、一句欢迎语。直接点着改也行，对助手说一句“馆名改成××，用蓝色”也行。改之前能先看到学生那边的样子，满意了点“用这个样子”才生效，随时能恢复上一版。

四、学生怎样进入您的社区

  1. 您在“管理”里点邀请学生，得到一个链接和二维码，发给学生（微信即可）。链接 7 天内有效，过期再生成一个。
  2. 学生打开链接，先看到您的馆，点开始使用。
  3. 学生接入自己的大模型（DeepSeek、通义千问、Kimi、豆包都可以），填一次钥匙，点“测试连接”。
  4. 进入镜子页，页首写着您的馆名和称呼。从此学生就在您门下了。
没有公开注册，也没有“搜馆”：学生只能经您的邀请进来。一个学生可以同时跟几位老师，彼此的方案、病历、账目不会串。

五、学生每天做什么

  • 照镜子：看当天按当地太阳时算的时辰、节气和今日建议；拍一张舌象，留下舌头裁剪图和示意图，自己对照变化。
  • 做作业、打卡：作业是您签发的，挂在学生已有的习惯上，到点提醒。
  • 记一下自己的感受：“这段时间自己感觉怎样”只存在学生自己手机上，您看不到，也不会随问诊发出。
  • 不舒服时问诊：说清楚哪里不舒服，助手追问、整理成卡片，学生核对后点“发给老师”。

六、您每天做什么

页面做什么
今天看今天有哪些学生发来问诊、哪些在等您。
远程打开学生的问诊，看助手起的病历草稿；舌象左边是裁剪图、右边是示意图，看不准的您逐项改。改完亲手签字发出，病历和作业就到了学生手机上。签字时可以顺手点一下“和上次比：改善 / 持平 / 变差 / 说不准”，不点也能签。
面诊学生当面来时，直接在这里写病历、签字。
管理邀请学生、说一句话记账、改门面、设“记录保留多久”（默认 90 天，可设 30 天到 3 年）。

七、几条不会变的规矩

  1. 签字只能您本人。助手只起草，病历和方案经您亲手签字才算数。
  2. 急症提醒不能关。学生说到急重症信号，第一句话永远是“请尽快去医院”。
  3. 没人能冒充您。学生只认您本人签名的东西；别人起一个同名的馆，学生那边不会显示。
  4. 原图不留。舌象照片只留舌头那一块，认不出是谁；原图当场清掉。
  5. 资料在各自手机上。没有中心数据库；学生的记录在学生手机上，您签过的病历在您手机上，按您定的保留期限自动清理。您和学生互为备份。
  6. 社区不经手钱。钱在您和学生之间走，账由您自己的助手记。

八、换手机怎么办

  • 学生换手机：您生成一个“学生换手机”链接发给他。他打开后说“我是原来的某某”，您这边会问“小王说他换了手机，是他吗？”，您点“是”，他保留期内的记录和钱账余额就自动回去了。
  • 您换手机：您生成“老师换手机”链接，逐个发给学生；学生点“是她”以后，您的记录由学生自动发回给您。学生没点之前，新手机签的东西学生一律不收。
  • 家人跟着管理人一起认回，不用您逐个确认。

第二部分

九、在国内落地的做法（给技术人员）

这一部分写给帮老师安装的技术人员。系统是开源的，代码在 GitHub 公开仓库 Jordani-Ho/Aster-Ai，部署文件在 deploy/home/。

1. 系统由哪几块组成

部分做什么
手机网页应用（web）老师和学生打开的就是它，可“添加到主屏幕”像 App 一样用。
中继（relay）在老师和学生的手机之间传消息（Nostr 协议，消息端到端加密，中继看不到内容）。
模型网关（gateway）推送提醒；使用者自己的模型调用失败时做后备。
对外入口让手机从外网访问上面两个地址：路线 A 用隧道，路线 B 用域名加反向代理。

全部用 Docker 跑。数据只在部署机器的 deploy/home/data/ 里，不进仓库。

2. 国内网络要先处理的事

  • Docker 镜像：Docker Hub 在国内常拉不动，请先配好镜像加速源。
  • 编译依赖：中继要在容器里编译 Rust（约 10 到 30 分钟），请为 crates 配国内镜像；Node 依赖可配 npm 国内镜像。
  • 拉代码：GitHub 慢的话，可先下载压缩包或用镜像。
  • 大模型：老师和学生各自用国内的模型即可（DeepSeek、通义千问、Kimi、豆包都已内置），在应用里填自己的钥匙，不用在服务器上配。

3. 路线 A：装在老师自己的电脑上

适合先试用。电脑要一直开着。

  1. Windows 电脑装 WSL2 + Ubuntu（或直接用一台 Linux 电脑），装好 Docker（含 compose）、Node 22、git、curl。
  2. 进入仓库的 deploy/home/： 
    cp .env.example .env
./quick-start.sh
    脚本最后一行打印出手机可以直接打开的网址。
  3. 验收：./verify.sh，六项都应 PASS。
脚本默认用 Cloudflare 临时隧道对外，网址每次重启都会变，在国内也可能时快时慢。如果不稳定，可以换成国内的内网穿透服务，把两个地址分别指到 web:8080（应用）和 relay:8080（中继，WebSocket）；或者直接走路线 B。

4. 路线 B：装在一台云服务器上

适合长期使用：全天在线、网址固定。需要一台 Linux 云服务器（2 核 4 GB 内存够用）和一个域名。

  1. 域名下建两个子域名，都解析到服务器，例如 app.您的域名（应用）和 relay.您的域名（中继）。
  2. 在 .env 里填： 
    APP_DOMAIN=app.您的域名
RELAY_DOMAIN=relay.您的域名
VAPID_SUBJECT=mailto:您的邮箱
  3. 运行 ./setup.sh 生成配置，再启动三个服务： 
    docker compose up -d --build relay gateway web
  4. 加一个反向代理负责 HTTPS，接在同一个 Docker 网络里。用 Caddy 最省事，它会自动申请证书，也支持 WebSocket： 
    app.您的域名 {
    reverse_proxy web:8080
}
relay.您的域名 {
    reverse_proxy relay:8080
}
    服务器只需对外开 80 和 443 端口。
  5. 验收：./verify.sh。
路线 B 的反向代理部分，我们还没有在国内实际走过；遇到问题请联系发起人。服务器放在哪里、要不要备案等，请老师和技术人员按当地情况自己判断。

5. 装好以后：登记老师、邀请学生

  1. 在部署机器上查看一次性登记口令：cat deploy/home/data/teacher-setup-code.txt，只交给老师本人。
  2. 老师手机打开应用网址 → 选“我是老师” → 接入自己的模型 → 进“管理” → “我是这个社区的老师” → 输入口令 → 看到“社区已建立，可以邀请学生”。
  3. 老师在“管理”里改好门面，然后点“邀请学生”，把链接发给学生。

6. 日常维护

  • 停止（数据保留）：docker compose down（路线 A 加 --profile quick）。
  • 更新代码后重建：docker compose build --no-cache relay gateway web，再启动。
  • .env、data/ 和登记口令都不要外传、不要提交到任何仓库。
  • 服务器上只有加密后的消息和推送订阅；病历、舌象等都在老师和学生各自的手机里。

7. 遇到问题

先运行 ./verify.sh，看哪一项没过。把那一行的输出发给发起人，我们一起看。
