## 1. 一页纸

1. **修行院，不是医院。** 治未病社区只有教育，没有交易。老师是启发和指导的人，学生是自己健康的第一责任人。
2. **两端的核心是智能体。** 老师智能体是老师时间的放大器，学生智能体是学生习惯的辅导员；其余都是可插拔的工具。
3. **数据跟着人走。** 学生的一切在学生手机上；老师端只留保留期内的病历和名下学生的五项档案。没有中心数据库。
4. **只有老师本人能签字。** 智能体只起草；签字、入账的确认永远是人按的，路径上不调模型。
5. **就医提醒常在，不判断。** 问诊页顶端一直有一句就医提醒，不拦截、不判断急症和心理状况。
6. **原始材料用完即毁。** 舌象照片当场抽象、原图清掉；面诊的患处照片随签字病历交给学生；录音、逐句原话和老师端的患处原图在老师签字交还后删除。
7. **中间只有可替换的邮差。** 消息经端到端加密的 Nostr 中继传递；中继看不懂内容，30 天后过期。

## 2. 设计原则

| 原则 | 含义 | 反例（不要做） |
| :-- | :-- | :-- |
| 让使用者感受到尊重 | 严谨、专业、替人着想，落在每一处细节 | 照搬一般产品的套路；说教、吓唬 |
| 以老师为中心 | 要有人多做一步，让学生做，不让老师做 | 让老师填表、手抄口令 |
| 大道至简 | 能不建就不建；代码越少越直白越好 | 为“以后可能”预建抽象、开关 |
| 数据跟人走 | 谁的数据存在谁的设备上；给别人看是临时的 | 中心数据库 + 权限隔离 |
| 模型无关 | 提示词、模板、领域知识是纯文本文件 | 业务逻辑绑死某家模型 |
| 诚实边界 | 只把已实现的写成已实现 | 文档写了、代码里没有 |

## 3. 角色

| 角色 | 一句话 | 不能做 |
| :-- | :-- | :-- |
| 老师（真人） | 签字、定方案、定保留期限、记钱账、改门面 | — |
| 老师智能体 | 整理问诊、起草病历和方案、按排班邀约、提醒药材、到点按老师设的天数请出不打卡的学生 | 签字；确认入账；替老师答应他没答应的事 |
| 学生（真人） | 进馆填基础信息、问诊、照镜子、打卡 | — |
| 学生智能体 | 采集整理学生的话、抽象舌象、督促作业和复诊、催回邀约、管家里的药材 | 诊断；冒充老师；撒谎、吓唬、羞辱；把本人感受发出去 |
| 家里的管理人 | 为家人开子账户、代家人问诊 | 动别家的账 |

- **身份**是一对 secp256k1 密钥，公钥就是身份；名字只是显示用的称呼。界面上不出现“密钥、助记词、公钥”。
- 换手机靠**师生互认**找回身份（老师确认“是这位学生”），不靠助记词。
- 一个学生可以跟随多位老师；老师之间看不到学生在别处的任何内容。

## 4. 部件

| 部件 | 是什么 | 有没有状态 |
| :-- | :-- | :-- |
| 手机网页应用 | React + TypeScript + Vite 的 PWA，老师和学生同一套代码，按身份显示界面 | 有：本人数据，存在手机浏览器的 IndexedDB |
| 中继 | 开源 Nostr 中继（`relay/`，带社区成员鉴权补丁） | 只有待投递的加密消息，30 天过期 |
| 网关 | `gateway/`：后备模型转发、进馆邀请兑换与成员名单、推送转发 | 成员名单与推送订阅；**不记录内容** |
| 推送 | 标准 Web Push，只说“有新消息”，不带内容 | 只有订阅令牌 |
| 社区仪表盘 | 每个馆只交统计数，我们只看不改 | 统计数 |

- 消息格式：NIP-17 私信、NIP-44 加密、NIP-59 礼物包裹；外层用一次性密钥，时间随机化。不自造加密。
- 本机存储是普通 IndexedDB，不另加密：隐私靠**抽象化**（只留特征、不留原图），不靠加密层。
- 模型：每位老师、学生先接自己的模型（DeepSeek、千问、OpenAI 兼容接口、本地模型）；没有时可用社区网关的后备模型，或只走规则。

## 5. 数据：谁存什么

| 数据 | 存在哪 | 何时删除 |
| :-- | :-- | :-- |
| 基础信息（称呼、性别、出生年月日时、出生地、居住城市、作息、病史、用药、过敏、西医诊断） | 学生手机 | 学生决定 |
| 照镜子、舌象特征与裁剪图、打卡、坚持记录、督促记录、本人感受 | 学生手机 | 学生决定；督促记录和感受永不外传 |
| 签字病历（完整）、调养方案、作业 | 学生手机；老师手机留保留期内的一份（师生互为备份） | 学生决定；老师端按保留期限 |
| 名下学生档案：称呼、性别、年龄、健康八字、居住城市 | 老师手机 | 学生被请出或离开时 |
| 问诊包里的录音、逐句原话、问答；面诊录音、逐句原话、患处原图 | 老师手机（临时） | **老师签字交还后删除**（患处照片同时随签字病历交给学生） |
| 学生家里的药材快照 | 老师手机，随这次问诊 | 跟问诊包同一保留期限 |
| 老师模板、思想指纹、钱账 | 老师手机 | 老师决定 |

- **年龄和八字每次重新算**，出生日期和时辰不离开学生手机；八字只按出生地算，没有出生地就没有八字。
- **抽象一步一步来**：舌象只留特征值、示意图和只有舌头的裁剪图，原图当场清掉；模型看不准就说“不确定”，老师说了算。

## 6. 核心闭环

1. **开馆**：老师接模型（可跳过）、登记、起馆名、开馆。六项开馆准备（模板、排班、邀约方式、药材库、保留期限、模型）**都是建议，不是门槛**；没填的按默认走：没排班就不约面诊，没设药材库就按不备药。
2. **邀请**：老师签发邀请链接（第一位 1 小时、之后 7 天有效），学生扫码进馆。
3. **进馆**：学生先填基础信息（必填：称呼、性别、出生日期、出生时辰〔可选“实在不知道”〕、出生地、居住城市、作息），填完才进首页。
4. **问诊**：学生说话、打字、按住录音；智能体按老师的问诊模板追问；原话逐句编号、一字不改，整理只引用序号，追问回答单独成对。学生核对后点“发给老师”，这是数据离开手机的唯一入口。远程问诊可附上家里的药材。
5. **整理与签字**：老师智能体按本馆模板再整理一次（只看原话，不收音频），起草病历和方案；老师核对、修改，本人签字。库存不够不挡签字，只提示。
6. **交还**：签字病历加密发回学生；作业进入学生智能体的督促；老师端删除录音和逐句原话。
7. **日常**：学生每天照镜子（也是验算有没有复发）、打卡；学生智能体按 7.3 节督促。
8. **预约**：老师智能体按排班给有一段时间没来的同城学生发具体时段，2 小时不回就请下一位，可以超约；同城学生也可以自己请求 1–3 个时段。面诊只约同城（两边都填了城市且不同才算异地）；学生改了居住城市，老师随即知道。
9. **面诊**：老师点「开始录音」，师生当面对话，浏览器边听边转文字；停止或中断时，老师智能体按本馆模板把原话整理成主诉、现病史和望闻问切（每栏标原话序号）。望可拍舌象（当场抽象）和患处（原图进病历）；切由老师记脉象。老师改、签字发给学生。
10. **请出与回来**：老师设了天数，学生有作业却超过天数不打卡，两个智能体到点自动执行：先通知学生，再从名单移除。这只是虚拟世界里失联，现实中的面诊照常。没有“恢复”，只有老师重新邀请。

## 7. 智能体规范

### 7.1 四件事

每个智能体只由**角色、记忆、主动、守线**四件事组成，不属于这四件的都是工具（排班表、药材库、录音、舌象、天时、钱账、体态、统计）。工具只管数据和规则，不自己判断；以后换外壳时拆成技能，别人可以重写。详见 `docs/智能体架构.md`。

### 7.2 一事一议

```
触发（到点 / 收到消息 / 人点了一下）→ 只取这件事的材料（有额度上限）
→ 规则或模型（能用规则就不调模型）→ 草稿 → 真人确认（或模板允许自动）→ 发出或记下 → 忘掉
```

- 同一件事、同一个对象、同一天只做一次（幂等键：端 + 任务 + 对象 + 本地日）。
- 对外发送必须是本机名单里的人；同一任务同一收件人至少隔两小时。
- 产出里不得伪造老师的字段（来源标签不能是 `teacher`）。

### 7.3 学生智能体的督促

- 督促的话全部来自固定话术（`prompts/student/nudge.md`）加本机真实数据，**不用模型生成**；话术和数据都过禁用词检查，缺数据整句不发。
- 作业到点没打卡：先温和提一次；当晚没动再提一次；之后每天一次，并摆出“这周 x/y，上周 x/y”。照镜子、复诊、邀约快到期、到睡觉时间也各有一套。
- 学生把智能体晾着时：到老师设的天数 L 的一半，说一次事实；还剩 7 天，退一步不再天天催；老师没设时分别是第 7、14 天。学生任何一次行动，就算回来了。
- 学生不能关掉督促；督促记录只留学生本机。

### 7.4 学习

- **只向老师的签字学。** 老师亲手改过的地方和加减理由分量最重；一字未改就签的只算“认可”。
- **思想指纹** = 老师的模板 + 签了字的医案 + 每次“草稿 → 定稿”的改动。起草时作为上下文，不做模型微调。
- 学生智能体对照老师智能体的整理来学，最多带最近五对“我的整理 / 老师的整理”。

### 7.5 签字

- 签字只能由老师本人在界面上按下；签字模块不得导入模型模块。
- 学生端只显示带有效老师签名的病历和医嘱；签名不符的一律丢弃。

## 8. 就医提醒

- 问诊各步顶端**始终**显示同一句：“急症请立即去医院或拨打当地急救电话，别等老师回复。”
- 不能关，不拦截发送，不显示电话号码。
- 智能体和代码都不按学生的话判断急症或心理状况：不弹提醒、不打标记、不排先后。

## 9. 治理

- **社区是天然的过滤器。** 平台不评判谁好谁坏，不设评分、排行、公示栏，也不封存老师。
- **老师是邀请制**：由核心成员（发起人、技术合伙人和最早的几位老师）推荐师德可靠的人。（未做，见 13 节。）
- **学生的资格由他的老师说了算**：老师设多少天不打卡就请出名单（默认不设），到点由智能体执行。
- **康币是公开的尺**：差的老师，学生越来越少，康币也越来越少，人人看得见（见 10 节）。
- **师承**：老师可指定接火人；交接后的智能体改名“某某门智能体”，不能用原老师的身份签字。学生可以随时离开某位老师，本机资料不受影响。
- **道医**是知衡里的一个门派，共用社区、康币和老师邀请制，守同一部医纲。

## 10. 两本账

- **钱账**：学生在社区外把钱付给老师，老师对智能体说一句话就记上，本人核对后亲手确认入账。只是记录，平台不经手钱，也不做支付接口。
- **康币账**：康币是健康财富的量度和记账工具，跟钱没有直接关系。钱换生活质量，康币换生命质量。单位“刻”（15 分钟），康币 = 时间 × 效果；效果由老师判断和智能体实测来量，本人感受不进康币。康币只在智能体之间流通，只锚定比特币。
- 两本账分开，不互相兑换。**内测期间康币只观察、不发放**；规则数值全部未定，由发起人定。详见 `docs/proposals/康币定义.md`。

## 11. 开发协作

| 角色 | 由谁 | 做什么 | 不做 |
| :-- | :-- | :-- | :-- |
| 发起人 | 真人 | 哲学和产品拍板；C 类决定 | 不需要看代码 |
| 技术合伙人 | Claude | 维护本文；写任务卡；审核并合并；里程碑验收 | 不审自己写的代码 |
| 智能体本身 | Codex（或技术合伙人写、Codex 审） | 角色、记忆、主动、守线 | — |
| 工具、界面 | DeepSeek | 按任务卡实现并自测 | 不改本文 |

1. **施工的人不审自己的代码。**
2. **每张卡先写验收用例**，一卡一分支一合并请求。
3. **main 受保护**：必须走合并请求，app、gateway、e2e 三项 CI 全过才能合并，谁都不能绕过。
4. **三级决策**：A 类（界面文字、修 bug）施工者直接做；B 类（数据格式、流程、对外措辞）技术合伙人审核，并写进 `docs/schemas/`；C 类（就医提醒、隐私、康币、医纲、请出规则的数值）发起人决定。
5. **只用合成数据**：仓库、测试、日志里不得有真人的资料、照片和录音。
6. **领域可扩展**：中医内容只放 `domain/tcm/`、模板和工具里，不渗进智能体骨架（角色、记忆、主动、守线、身份、中继、签名、康币记账）；以后做衣食住行时骨架可以直接拆出来用。
7. **测试**：Vitest 单元测试；浏览器用例（Playwright）；双手机经**真实中继**的端到端用例，不允许假中继。

## 13. 还没有的（诚实边界）

- **进馆通知不能证明发件人兑换过邀请**：老师端只核对邀请是老师本人签的、网关网址对、晚于请出时间；有效期在学生兑换时由网关核验。拿到别人进馆链接的人，可能绕过网关直接发进馆通知。内测人少，先这样；以后让老师端向网关确认发件人是成员。
- **在线实时指导与在线预约**：现在只有面诊预约（只限同城）和时差远程问诊。
