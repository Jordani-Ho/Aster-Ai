# M1-04 急症红线引擎

- 状态：已完成（2026-10-16 合并，施工 DeepSeek，审核 Claude）
- 依赖：无
- 白皮书依据：§5.4
- 决策级别：**C 类**。红线清单的增删改须经发起人确认；引擎实现属于 A / B 类。

## 目标

学生智能体在采集和日常对话中，一旦发现急重症信号，立即中断其他流程，提示就医。

## 范围

要做的：
- `domain/tcm/red-flags.json` 已有初版清单。引擎从这里读取规则，**不在代码里硬写任何词**。
- `app/src/core/redflags/`：`check(text) → { hit: boolean, category, matched }`。
  - **第一层（必须）**：本地确定性匹配，按清单里的关键词和组合规则匹配。不依赖网络和大模型，离线也能工作，结果可以复现。
  - **第二层（可选，留接口）**：交给大模型二次判断。只允许“增加命中”，不允许把第一层的命中改成不命中。
- 命中后的界面：全屏提示“请立即就医”，按用户所在地区显示急救电话；自伤类显示心理援助热线。留一个“通知老师”的接口，等 M1-05 接通后再发送。
- 用户可以点“我已知晓”关闭提示，关闭操作记入本地日志。

不做的：
- 诊断或分诊结论。界面只说“请就医”，不说“你可能是某某病”。

## 验收用例

1. `red-flags.json` 里的每一类，至少有 3 条应该命中的口语例句和 3 条不应该误报的例句，例如“昨天跑步胸口有点闷，休息一下就好了”。全部写成测试。
2. 断网时引擎照常工作。
3. 模拟第二层大模型返回“不命中”时，第一层的命中依然有效。
4. 按地区显示的急救电话与清单一致。
5. 删除清单中任何一条时，CI 中的“只增不减”检查失败（与上一版本比较条目 ID）。
