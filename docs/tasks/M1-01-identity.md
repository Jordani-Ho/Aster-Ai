# M1-01 身份：密钥与助记词

- 状态：待领
- 依赖：无
- 白皮书依据：§2（身份）、§4.4（备份）

## 目标

每个使用者第一次打开应用时生成自己的身份（一对 secp256k1 密钥），用 12 个助记词备份，并且能用助记词在另一部手机上恢复。

## 范围

要做的：
- `app/src/core/identity/`：生成助记词（BIP-39，12 词，支持中文词表和英文词表）、由助记词派生密钥（按 Nostr 的 NIP-06 派生路径）、导出公钥（npub 格式和十六进制）。
- 被照护者子身份：从同一组助记词按账户序号派生（序号 0 为本人，1、2…… 为被照护者）。
- 界面流程：生成 → 抄写 → **随机抽 3 个词核对** → 完成；核对不通过不能进入下一步。
- 恢复流程：输入 12 个词 → 校验 → 恢复身份。
- 私钥只存在内存和 M1-02 的加密存储里，**不写进 localStorage，不打印日志**。

不做的：
- 加密存储层本身（M1-02）；
- 与中继通信（M1-05）。

## 建议依赖

`nostr-tools`、`@scure/bip39`。新增依赖属于 B 类决策，在合并请求里列出版本和许可证。

## 验收用例

1. 用 NIP-06 规范里公布的测试向量（助记词 → 私钥 → 公钥）做单元测试，结果完全一致。
2. 同一组助记词恢复两次，得到的公钥相同；改错一个词，校验失败并提示。
3. 账户序号 0 和 1 派生出的公钥不同；用同一组助记词重复派生，结果稳定。
4. 抄写核对时输错一个词，不能进入下一步。
5. 在全部源码里搜索 `console.log`，与私钥、助记词相关的路径没有任何输出。
