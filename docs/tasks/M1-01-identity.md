# M1-01 身份：密钥与助记词

- 状态：已完成（2026-10-16 合并，施工 Codex，审核 Claude）
- 依赖：无
- 白皮书依据：§2（身份）、§4.4（备份）

## 目标

每个使用者第一次打开应用时生成自己的身份（一对 secp256k1 密钥），用 12 个助记词备份，并且能用助记词在另一部手机上恢复。

## 范围

要做的：
- `app/src/core/identity/`：生成助记词（BIP-39，12 词，支持中文词表和英文词表）、由助记词派生密钥（按 Nostr 的 NIP-06 派生路径）、导出公钥（npub 格式和十六进制）。
- 被照护者子身份：从同一组助记词按账户序号派生（序号 0 为本人，1、2…… 为被照护者）。
- 界面流程：生成 → 抄写 → **随机抽 3 个词核对** → 完成；核对不通过不能进入下一步。
- 恢复流程：输入 12 个词 → 校验 → 恢复身份。
- 私钥只存在内存和 M1-02 的加密存储里，**不写进 localStorage，不打印日志**。

不做的：
- 加密存储层本身（M1-02）；
- 与中继通信（M1-05）。

## 已定事项（2026-10-16，PR #2 答复）

1. **词表**：生成时支持**简体中文（默认）**、繁体中文、英文三种；恢复时自动识别是哪种词表（用三份词表分别校验，校验和通过的那份即是）。身份资料里记下所用词表。
   - 不同词表的助记词派生出的密钥不同，这是 BIP-39 的标准行为，不需要特殊处理，但界面上要提示“请用生成时的同一种文字恢复”。
   - 简体和繁体词表有大量相同的汉字，一组助记词可能同时通过两份词表的校验。这没有问题：种子由助记词文字本身算出，文字相同，密钥就相同。识别时按“简体 → 繁体 → 英文”的顺序取第一个通过的即可。
   - 中文词表每个词是一个汉字，12 个汉字比 12 个英文单词更容易让老年用户抄写。
2. **不使用 BIP-39 密码短语**（passphrase 为空），避免用户忘记第二个秘密。
3. **NIP-06 标为 unrecommended 的处理**：继续使用助记词。官方建议“直接用单个私钥”，但对本项目的用户来说，抄写一长串 nsec 私钥既容易出错，也无法恢复被照护者的子身份。保留 NIP-06 的派生路径 `m/44'/1237'/<account>'/0/0`，本人用 account 0，被照护者用 1、2、3……；同一组助记词可以恢复全家人的身份。
4. **依赖已批准**（固定确切版本，不用 `^`）：`nostr-tools@2.25.2`（Unlicense）、`@scure/bip39@2.4.0`（MIT）、`@scure/bip32@2.4.0`（MIT）。中文词表的生成和校验用 `@scure/bip39` 自带的词表；派生可以用 `nostr-tools` 的 NIP-06 函数，也可以用 `@scure/bip32` 直接派生，两者结果必须一致。

## 验收用例

1. 用 NIP-06 规范里公布的两组测试向量（助记词 → 私钥 → 公钥）做单元测试，结果完全一致。
2. 简体、繁体、英文三种词表各自完成“生成 → 恢复”往返测试，公钥一致；恢复时能自动识别词表。中文词表没有官方测试向量，**不得自行编造向量**，改为用 `nostr-tools` 和 `@scure/bip32` 两条路径交叉验证结果一致。
3. 同一组助记词恢复两次，得到的公钥相同；改错一个词，校验失败并提示。
4. 账户序号 0 和 1 派生出的公钥不同；用同一组助记词重复派生，结果稳定。
5. 抄写核对时输错一个词，不能进入下一步。
6. 在全部源码里搜索 `console.log`，与私钥、助记词相关的路径没有任何输出。
