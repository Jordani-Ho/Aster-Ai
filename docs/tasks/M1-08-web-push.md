# M1-08 网页推送

- 状态：待领
- 依赖：M1-05
- 白皮书依据：§3、§9

## 目标

老师收到问诊、学生收到签字病历时，手机能弹出提醒。提醒里只有“有新消息”几个字，不带任何内容。

## 范围

要做的：
- `app/`：注册 Service Worker，订阅标准的网页推送（Web Push，VAPID）。
- `gateway/push/`（与模型网关同一个服务或独立部署都可以）：
  - 保存“公钥 → 推送订阅”的对应关系，用户可以随时注销；
  - 提供“提醒某个公钥”的接口，调用方必须带成员签名（NIP-98），并按调用方限流，防止骚扰；
  - 推送内容固定为“知衡：有新消息”，**不接受调用方传入的任何文字**。
- 发送方在中继发出消息后，调用一次提醒接口。
- 兜底：不支持推送的环境（iOS 未“添加到主屏幕”、微信内置浏览器）在打开应用时自动同步，并在首页提示“添加到主屏幕可以收到提醒”。

不做的：
- 原生 App 推送（APNs、FCM）。

## 已定事项（2026-10-16，派卡前补充）

1. **推送服务放进现有的 `gateway/` 服务**，新增 `/push/subscribe`、`/push/unsubscribe`、`/push/notify` 三个路由，沿用网关的 NIP-98 鉴权、防重放、请求体上限和限流。网关原有的“只放行 `/v1/chat/completions`”改为“只放行这四个路径”，其他路径仍然返回 404。
2. **依赖已预先批准**：`web-push@3.6.7`（MPL-2.0，2024-01 发布），仅用于网关，固定确切版本。不需要再申请。
3. **订阅数据要保存**：推送服务是网关里唯一有状态的部分。用一个 JSON 文件 `push-subscriptions.json` 保存“公钥 → 订阅”，写入时先写临时文件再改名，避免写坏。M1 规模很小，够用。这个文件**不进仓库**，加进 `.gitignore`。
4. **VAPID 密钥从环境变量读取**，不写进文件。README 里写明如何生成。
5. **与中继的衔接**：在 `app/src/core/push/` 提供 `notifyRecipient(pubkey)`。M1-05 合并前，不接入发送流程；合并后由后续任务接上。
6. **iOS 的限制**：只有“添加到主屏幕”以后才能收到推送。首页检测到没有添加时，显示一句提示。

## 验收用例

1. 在支持推送的浏览器里，A 发消息给 B，B 收到提醒，提醒文字固定。
2. 调用方试图传入自定义文字时被忽略。
3. 注销订阅后不再收到提醒，服务器上的对应记录被删除。
4. 同一调用方 1 分钟内对同一公钥提醒超过 5 次，多余的被丢弃。
5. 不支持推送的环境里，打开应用后能看到新消息，首页显示“添加到主屏幕”的提示。
6. 订阅文件在写入过程中被中断（模拟崩溃），原文件仍然完好。
7. `/v1/chat/completions` 以外、推送三个路由以外的路径仍然返回 404。
