# M1-12 面诊记录模式

- 状态：已派（DeepSeek，接在 PR #18 之后）
- 依赖：M1-10、M1-11、M1-09（照片处理）
- 白皮书依据：§5.1（“面诊记录：老师当面看诊，老师端拍照、起草，签字后发给学生”）

## 目标

学生到老师面前看诊时，由老师在自己手机上录入，起草、签字后照常交还给学生。

## 范围

要做的：
1. 老师端新建一份 `kind: 'in_person'` 的病历，选定学生（从老师已有的学生索引里选，需要学生公钥）。
2. **主诉等由老师代录**：`intake` 各项来源为 `teacher`，`note` 写 `in_person`。
   - **这是对硬规则的唯一例外**（病历格式第 3 节第 2 条）：`signEncounter` 和学生端 `verifySignedEncounter` 只在 `kind === 'in_person'` 时允许 `intake` 来源为 `teacher`；其他 kind 照旧只许 `student`/`unknown`。技术合伙人负责同步更新 `docs/schemas/encounter.md`。
   - 学生端显示这份病历时，在主诉旁标“老师代录”。
3. 老师当面拍照（舌象），复用 M1-09 的 `photo.ts`（缩放、去 EXIF）。
4. 起草（M1-10）、审改签字和交还（M1-11）全部复用，不另写一套。急症红线照样对老师录入的文字做检查，命中时提示老师“请立即安排就医”，但不阻止老师继续记录（老师在现场，由老师判断）。
5. 签字交还后，老师端同样执行诊毕即还：照片和代录原文不留。

不做的：录音、语音识别；实时远程（`remote_live`）。

## 验收用例

1. 面诊病历 intake 来源为 teacher 时可以签字；同样的病历把 kind 改成 `remote_async` 就签不了。
2. 学生端收到面诊病历能通过校验，主诉旁显示“老师代录”；把 kind 改成 `remote_async` 重新签名的病历被学生端拒收。
3. 老师录入“胸口压着疼，出冷汗”：显示就医提示，记录可以继续。
4. 签字交还后，老师端查不到这次的照片和 intake 原文。
5. 375px 截图放 `docs/screenshots/`。
