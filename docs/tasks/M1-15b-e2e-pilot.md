# M1-15b 端到端验收与试点指标

- 状态：进行中（Codex，2026-10-17）。阶段 1 测试环境见草稿 PR #21；完整流程与试点指标等 M1-15a 合并后接上。
- 依赖：M1-15a
- 白皮书依据：§5.2、§10（M1 验收标准）

## 目标

用真实的中继、网关和浏览器，自动跑通一次完整问诊；导出 4 项试点指标。

## 范围

1. **测试环境**：`e2e/` 目录，Playwright（容器里已预装 Chromium，路径见 `PLAYWRIGHT_BROWSERS_PATH`；新依赖 `@playwright/test` 按规矩固定版本、满 14 天）。
   - 中继：按 `relay/Dockerfile` 的步骤编译 nostr-rs-relay（打两个补丁），本机进程启动。CI 里没有 Docker 也要能跑：写一个脚本完成“取上游固定提交 → 打补丁 → cargo build”，并缓存编译结果。需要 `protoc`，脚本里处理。
   - 网关：启动 `gateway/`，上游模型用本地替身（固定返回合成的起草结果），推送用替身。
   - 两个浏览器上下文：老师、学生，各自用合成助记词。
2. **完整流程测试**（白皮书 §5.2 九步）：学生说话（直接填文本框）、拍照（合成 JPEG）、追问、急症筛查（另一条用例触发）、确认发送 → 老师收到、起草、签字、扣费 → 学生收到病历、作业出现 → 学生打卡 → 学生复诊回到第 1 步，附带上次病历。
3. **四条硬性验收**：
   - 老师端签字后，在老师浏览器的 IndexedDB 里搜不到学生原话和照片字节（解密后搜）；
   - 学生端只显示有效签名的病历；
   - 师生两端余额和对账码一致；
   - 清空学生浏览器后用助记词恢复，病历、作业、账本都回来。
4. **试点指标**（本机计算、本机导出，不上传）：老师端“设置 → 导出试点指标”生成一个 CSV：
   - 每次起草到签字的耗时；
   - 老师对草案的修改率（`modificationLog` 里 AI 原文与定稿不同的字段数 ÷ 起草字段数）；
   - 关键字段缺失率（签字时仍为 `unknown` 的 intake 与四诊字段数 ÷ 总数）；
   - “像不像我”评分：签字后弹一次 1～5 分，可跳过。
   CSV 不含任何学生身份或病历内容，只有病历 id 的前 8 位和数字。
5. CI 加一个 `e2e` 任务。

不做的：真实手机测试、部署（另行安排）。

## 验收用例

1. `npm run e2e` 在干净环境里一条命令跑通（首次编译中继可能较慢，写明耗时）。
2. 上面四条硬性验收各有一条断言。
3. 导出的 CSV 用合成数据跑一遍，人工检查不含原文。
4. CI 的 e2e 任务通过。
