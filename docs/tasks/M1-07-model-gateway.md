# M1-07 模型网关

- 状态：待领
- 依赖：无（成员校验部分依赖 M1-01 的公钥格式）
- 白皮书依据：§3、§6.3

## 目标

学生不需要自己申请大模型 API Key。应用把请求发给社区的模型网关，网关转给大模型，**不记录任何内容**。

## 范围

要做的：
- `gateway/`：一个很小的 Node.js 服务，目标是 100 行左右，任何人都能读懂、都能自己部署一份。
  - 接收 OpenAI 兼容格式的请求，转发给配置好的上游（DeepSeek、Claude 或任何 OpenAI 兼容接口），支持流式返回。
  - 鉴权：请求必须带社区成员的签名（Nostr 的 HTTP 鉴权规范 NIP-98），公钥在成员名单里才放行。
  - 按公钥限流，例如每分钟 20 次，具体数值放在配置文件里。
  - 日志只允许记录：时间、公钥的前 8 位、耗时、状态码。**不得记录请求或回复的内容。**
- `app/src/core/llm/`：应用侧的客户端，支持三种来源：社区网关、用户自己的 API Key、本地模型地址。

不做的：
- 提示词本身（放在 `prompts/`，由各业务卡负责）；
- 计费。

## 验收用例

1. 没有签名或签名无效的请求返回 401。
2. 非成员公钥返回 403。
3. 成员请求能拿到上游的回复，流式返回正常。
4. 跑完测试后检查网关日志，找不到测试请求里的任何一段文字。
5. 超过限流时返回 429。
6. 改一行配置就能切换上游模型。
