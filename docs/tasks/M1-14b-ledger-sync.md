# M1-14b 康币账本同步与对账

- 状态：已派（Codex，2026-10-17）
- 依赖：M1-05、M1-14a（均已完成）
- 白皮书依据：§8.2
- 决策级别：B 类。本卡不改任何康币规则（规则见 `team/decisions.md` 和 M1-14a 卡）；遇到需要改规则的地方停下提问（C 类）。

## 目标

让同一本账在老师和学生两部手机上保持一致；任何一方删改、漏记，另一方都能发现并提示。

## 范围

要做的：`app/src/core/ledger/sync.ts` 及本机存储，经 `core/transport` 收发。
1. **三种应用信封**（`Envelope.type`）：
   - `ledger.event`：老师每记一笔，立即发给学生，payload 是签名事件；
   - `ledger.dispute`：学生提出异议，发给老师，payload 是签名异议；
   - `ledger.sync`：任一方请求对账，payload `{ teacher, student, length, head }`；对方回一条 `ledger.sync`，带上自己的全部事件（M1 规模小，整本发）。
2. **收到事件时**逐条用 `verify` 校验；按事件 id 幂等（重复收到不重复记账，传输层的去重只在内存里）。
3. **发现问题就标记，不自动修复**，界面显示一句话，让师生自己核对：
   - 对方的账比我短，或缺了我已有的某条：“对方账本缺少第 N 条”；
   - 同一个前序哈希下出现两条不同的事件（老师端分叉）：“账本有冲突，请与老师核对”，此时不显示余额；
   - 签名或链校验失败的事件不入账，记一条本地提示。
4. **异议的时间**（2026-10-17 定，取代原写法）：以学生**自报时间**判断是否在扣费后 7 天内；自报时间早于扣费时间、或晚于老师收到时间的，拒收并回说明。老师收到时间比自报时间晚超过 24 小时的，照样入列表，但标“迟到 N 天送达”给老师看。理由：老师离线几天时，按收到时间判断会冤枉准时提出异议的学生；异议本来就不改余额、只供师生协商，标出来就够了。`app/src/core/ledger/README.md` 同步改成这个口径。
5. **对账码**：两端都显示“余额 + 链尾哈希前 6 位”，师生当面或电话里念一遍就能确认一致。
6. 打开应用时、收到推送后，各自发一次 `ledger.sync`。
7. 存储：每本账一个集合，加密存本机（`core/store`），并登记到 `core/store/README.md`。

不做的：
- 界面里的记账操作页面（M1-15 前另行安排，或由本卡顺手做最简单的列表页，不强求）；
- 任何康币规则的改动、任何真实支付。

## 验收用例（用两个 `createTransport` 加内存中继替身，参照 `transport.test.ts`）

1. 老师充值 10、扣费 3，学生端余额为 7，两端对账码相同。
2. 学生离线期间老师记了 3 笔；学生上线后发 `ledger.sync`，补齐，余额一致。
3. 同一条事件收到两次，余额不变。
4. 老师端删掉中间一条后对账：学生端提示“对方账本缺少第 N 条”。
5. 构造同一前序哈希下的两条不同事件：显示冲突，不显示余额。
6. 自报第 6 天、老师第 9 天才收到的异议：入列表，标“迟到 3 天送达”，余额不变；自报第 8 天的：拒收并回说明；自报时间晚于收到时间的：拒收。
7. 篡改金额的事件：不入账，有本地提示。
