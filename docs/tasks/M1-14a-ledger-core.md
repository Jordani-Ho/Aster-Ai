# M1-14a 康币账本核心（纯逻辑）

- 状态：已完成（2026-10-16 合并，施工 DeepSeek，审核 Claude）
- 依赖：M1-01
- 白皮书依据：§8.2
- 决策级别：账本规则属于 **C 类**（康币）；实现细节属于 A / B 类。

## 目标

实现“每位老师一本账”的康币账本核心：记账、算余额、发现篡改、提出异议。本卡只做纯逻辑，不联网；在师生两部手机之间同步的部分放到 M1-14b（依赖 M1-05）。

## 范围

要做的：`app/src/core/ledger/`，全部是纯函数加类型定义，不依赖网络和界面。

1. **账本**：一本账属于一对（老师公钥，学生公钥），里面是按顺序排列的事件。
2. **五种事件**，每条都由签发人用私钥签名（Schnorr，复用 `nostr-tools`），并引用上一条事件的哈希，形成链：

| 类型 | 签发人 | 内容 |
| :-- | :-- | :-- |
| `topup` 充值 | 老师 | 金额、学生在社区外付款的方式说明（例如“微信转账”，可选） |
| `gift` 赠送 | 老师 | 金额、一句话说明 |
| `charge` 扣费 | 老师 | 金额、事由（`consult` 看诊 / `herbs` 药材 / `other` 其他）、关联的签字病历或药材清单哈希（可选） |
| `refund` 退款 | 老师 | 金额、针对哪条事件（可选） |
| `dispute` 异议 | 学生 | 针对哪条 `charge`、一句话理由 |

3. **余额** = 充值 + 赠送 − 扣费 − 退款。**允许为负**（即欠费，M2 的学生门规会用到“欠费持续天数”）。提供 `balance(ledger)` 和 `overdueSince(ledger)`：余额第一次变为负数并一直保持为负的起始时间。
4. **校验** `verify(ledger)`：逐条检查签名、签发人身份是否与事件类型相符、哈希链是否连续、金额是否为正整数、时间是否不倒退。任何一条不通过，就报出第几条、什么问题。
5. **异议**：学生只能在扣费后 **7 天内**（参数 P7）对某条 `charge` 提出异议，超期的异议校验不通过。异议不改变余额，只做标记，由师生自己协商；老师如果同意，就另记一条 `refund`。
6. **计价**：老师资料里声明 `{ currency: "CNY" | "USD" | ..., perCoin: 数值 }`，表示“1 康币相当于多少钱”。账本里只记康币的整数，不记任何真实货币金额。

不做的：
- 与中继同步、两端对账（M1-14b）；
- 界面；
- 任何真实支付。

## 结构约定（PR #9 审核时补充）

- **记账链只由老师写**（充值、赠送、扣费、退款），单一写入者，不会分叉。
- **异议不进链**，放在 `disputes` 列表里，由学生签名，用 `disputeFor` 指向扣费事件的 `id`。
- 异议时间由学生自报，可能倒填。M1-14b 收到异议时，按“实际收到的时间”核对。

## 发起人已确认的规则（2026-10-16）

| # | 问题 | 决定 |
| :-- | :-- | :-- |
| L1 | 学生退出师门或被封存时，剩余的预付余额怎么处理？ | 账本照常保留；老师可以记 `refund` 退款，系统不强制 |
| L2 | 赠送的康币能否用来退款？ | 不能。退款金额不得超过“累计充值 − 累计退款” |
| L3 | 老师能否在余额不足时扣费（形成欠费）？ | 能，余额可以为负 |

## 验收用例

1. 依次记充值 100、赠送 20、扣费 50、退款 10，余额为 60；两次计算结果相同。
2. 改动任何一条事件的金额，或者删掉中间一条事件，`verify` 都能报出出错的位置。
3. 学生签发的 `charge`、老师签发的 `dispute`，都校验不通过。
4. 扣费后第 8 天提出的异议，校验不通过；第 7 天提出的，可以通过。
5. 退款金额超过“累计充值 − 累计退款”时，校验不通过（L2）。
6. 余额在第 3 天变为负数，此后一直为负：`overdueSince` 返回第 3 天；中途补交充值、余额回正后，返回 `null`。
7. 金额为 0、负数或小数时，校验不通过。
8. 全部测试只使用合成的公钥和金额。
