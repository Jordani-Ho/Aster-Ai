# M1-17 无感上手：打开链接就能用

- 状态：已派（Codex，2026-10-17）
- 依赖：M1-01 至 M1-16
- 决策：发起人 2026-10-17 定（见 `team/decisions.md`）：密钥这道门槛太高，测试者不可能接受；用户界面上不再出现任何“密钥、助记词、公钥”。

## 目标

老师发一个邀请链接，学生点开就能问诊，全程不需要抄写、复制、粘贴任何东西。

## 原则

- **加密和签名照常在后台运行**，只是用户看不见。签字病历、康币账本、端到端加密都依赖它，拆掉反而要重写大半个系统，而且对用户没有任何好处。
- 界面上不出现“密钥 / 助记词 / 公钥 / npub / 十六进制”这些词。

## 范围

1. **首次打开自动生成身份**，不显示助记词，不要求抄写核对，直接进入首页。原来的生成与核对流程移到“设置 → 换手机时用（高级）”，默认收起。
2. **老师的邀请链接**：老师端“邀请学生”按钮，生成一个链接（并显示二维码），链接里带老师公钥和一张老师签名的邀请（NIP-98 风格的签名事件，含有效期，默认 7 天，可重复使用）。
   - 学生打开链接：自动生成身份 → 自动把这位老师加入“我的老师” → 自动向网关兑换邀请，成为成员 → 直接进入问诊首页。
   - 学生端同时把老师登记进康币账本（M1-14b 的 `open`）。
3. **成员资格自动化**：
   - 网关新增 `/invite/redeem`：校验邀请签名人是现有成员、未过期，就把学生公钥加进成员名单（原子写文件，与推送订阅同样做法），网关**不重启**即生效。
   - 中继：内测期间改为**接受任何通过 NIP-42 认证的连接**（新增配置开关 `community_open = true`，写进补丁；默认仍是白名单）。理由：中继上只有密文，链接本身不公开；真正花钱的模型网关仍然只对成员开放。部署配置默认打开这个开关。
   - 第一位老师（发起人指定）的公钥在部署时写进网关成员名单，作为“种子成员”；`deploy/home/setup.sh` 支持在老师手机上点“我是这个社区的老师”后，用一次性的部署口令把自己登记为种子成员，免去手工复制公钥。
4. **身份角色**：首次打开时只问一句“您是老师还是学生？”。从邀请链接进来的直接是学生。
5. **换手机/清缓存的风险提示**：首页底部一行小字“换手机前请到设置里备份”，不弹窗、不阻断。
6. 中继、网关、推送、备份等现有功能都不改行为。

不做的：账号密码登录、短信验证、任何中心化的用户数据库。

## 验收用例

1. 老师首次打开：只回答一个问题，就到了老师首页；全程界面上没有“密钥、助记词、公钥”字样（用 Playwright 抓全部可见文字断言）。
2. 老师点“邀请学生”得到链接；学生在另一个浏览器上下文打开链接，**不做任何输入**就进入问诊首页，“我的老师”和账本里已有这位老师。
3. 学生直接发起问诊，老师端收到（沿用 M1-15b 的完整流程，前置步骤换成邀请链接）。
4. 过期的邀请、非成员签发的邀请：兑换失败，学生端显示“邀请已失效，请向老师要一个新链接”。
5. 网关成员名单在兑换后立即生效，不重启。
6. 中继在 `community_open = true` 时接受任意认证连接；为 false 时行为与 M1-05 完全一致（原有测试全部通过）。
7. M1-15b 的 e2e 改用邀请链接流程后仍全绿。
