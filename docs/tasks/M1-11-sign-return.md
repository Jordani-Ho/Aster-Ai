# M1-11 审改、签字、交还与诊毕即还

- 状态：已派（DeepSeek，2026-10-16）
- 依赖：M1-01、M1-02（已完成）。草稿用 `docs/schemas/encounter.md` 格式的合成数据，不必等 M1-10。传输依赖 M1-05：已合并就接上，未合并就留接口。
- 白皮书依据：§4.1、§4.3、§5.2 第 6～8 步、§6.1、§6.2
- 共用约定：`docs/schemas/encounter.md`，类型在 `app/src/core/record/types.ts`（已存在，直接引用）

## 目标

老师在手机上审改智能体的草稿，逐项确认后签字。签字病历交还学生；老师端随即销毁原始资料，只保留去标识的医案和修改记录。

## 范围

要做的：
1. **审改界面**（手机，老师端）：按字段显示草稿，**用颜色区分来源**（学生陈述、老师判断、AI 草稿、未知）。每个 `ai_draft` 字段都有“采用”和“修改”两个操作。
2. **签字**（`app/src/core/record/sign.ts`）：
   - 只要 `fourExams`、`judgment`、`plan` 里还有一项是 `ai_draft`，签字按钮就不可用，`signEncounter()` 也直接抛错。这一条写进代码，不只靠界面；
   - 签名按 `docs/schemas/encounter.md` 第 2 节，生成 kind 2730 事件；
   - **签名的代码路径里不允许出现任何模型调用。** 用测试检查 `sign.ts` 不导入 `core/llm`。
3. **学生端校验**（`verifySignedEncounter()`）：签名有效、签名人是这位学生的老师、`p` 标签是学生自己，才接受并存入本地；否则拒绝，并给出原因。
4. **诊毕即还**（老师端，签字成功后立即执行）：
   - 从本地存储删除这次的问诊包和附件（照片、语音），写一条本地日志：时间和病历 id，不含内容；
   - 生成**去标识医案**存入老师本机，只含：`judgment`、`plan`、`outcome`，以及性别、年龄段（按 10 岁分档）。**不含**学生公钥、称呼、`intake` 原文和附件；
   - 记录“草案 → 定稿”的修改：逐字段记下 AI 原文和老师定稿，存进医案。这就是白皮书 §6.2 的思想指纹。
5. **新版本**：已签字的病历需要修改时，生成 `version + 1` 的新病历，`supersedes` 指向旧版的事件 id，重新签字。`id` 不变，只加版本号。**学生端**保留旧版，不覆盖；老师端只留索引 `{ eventId, encounterId, version, student, createdAt }`，不留病历内容（2026-10-16 审核 PR #15 时澄清）。
6. **交还**：把签名事件通过 `record.signed` 发给学生。M1-05 未合并时，调用一个 `send(type, payload)` 接口桩。

不做的：
- 起草（M1-10）；
- 作业提醒（M1-13）；
- 扣费（M1-14b）。

## 验收用例

1. 草稿里还剩一项 `ai_draft` 时，`signEncounter()` 抛错；全部确认后可以签字。
2. 签字后的事件能通过 `nostr-tools` 验签；改动 `content` 里任何一个字，校验失败。
3. 学生端：签名人不是自己的老师，或者 `p` 标签不是自己时，拒绝接收。
4. 签字后检查老师端本地存储的原始内容：找不到问诊包里的主诉原文，也找不到附件。
5. 去标识医案里找不到学生公钥、称呼和主诉原文；年龄只保留年龄段。
6. 修改记录里能看到某个字段的 AI 原文和老师定稿。
7. 修改已签字的病历：生成第 2 版，`supersedes` 正确，第 1 版仍然可以读取。
8. `sign.ts` 及其依赖里没有导入 `core/llm`（用测试检查）。
9. 界面在 375 像素宽的手机屏幕上可用，来源颜色可区分（附截图）。
