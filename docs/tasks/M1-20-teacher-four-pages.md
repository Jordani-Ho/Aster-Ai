## 范围

1. 底部四个标签：**今天 / 面诊 / 远程 / 管理**。
2. **今天**：待处理问诊数量，带急症标记的排最前并醒目显示；老师自己的镜子（复用 M1-18 的当日建议，调养方案由老师自己给自己定）。
3. **面诊**：M1-12 改成与学生问诊同样的对话式录入；起草与签字同“远程”。
4. **远程**：问诊列表 → 点开是一整张草稿卡片 → 输入框里说修改意见（“去掉黄芪”“作业改成每晚泡脚”），AI 按意见改稿（改后仍是 `ai_draft`）→ 一个“签字发出”按钮：按下时把卡片上全部 `ai_draft` 改为 `teacher`、`note: ai_accepted`，再走 M1-11 签字交还。可选扣费保留。
   - 同一页给这位学生“定制调养方案”（M1-18），一个输入框说要点，AI 整理成方案卡片，老师确认后签发。
   - 改稿提示词放 `prompts/teacher/revise-draft.md`，带防注入段。
5. **管理**：康币账本、模板、邀请学生（M1-17）、设置。
6. 签字路径仍然不得引用 `core/llm`（改稿在签字之前，属于起草阶段）。
7. 375px 截图四张。

## 验收用例

1. 老师从打开问诊到签字发出，不超过 3 次点按（不含说修改意见）。
2. 说“去掉某味药”，草稿方子里少了这味药，来源仍是 `ai_draft`；按“签字发出”后签名病历里没有任何 `ai_draft`。
3. 带急症标记的问诊在“今天”和“远程”列表里都排在最前。
4. 定制调养方案后，学生端镜子页第二天的建议引用了方案里的要点（用固定日期的模拟时钟测）。
5. M1-15b 的 e2e 改成新界面后仍全绿。
