# M1-22 家人子账户：一部手机照顾全家

- 状态：待派（排在 M1-21 之后，先空出来的施工者）
- 决策：发起人 2026-10-17 定，必须进内测（见 `docs/product/two-agents.md` 用户画像：40～50 岁“上有老下有小”）
- 康币：发起人 2026-10-17 定为**一家一本账**（见第 6 条）。
- 适用范围：家人账户只给**没有独立自理或支付能力**的家人（老人、孩子）。有独立能力的人自己开设账户和智能体，不放在别人名下。

## 目标

一个人在自己手机上替家里的老人和孩子建家人账户，替他们照镜子、问诊、打卡、收老师的方案；家人不需要自己的手机。

## 范围

1. **身份**：每位家人是一个独立身份，用同一份根身份按 NIP-06 的 `account` 序号派生（0 = 本人，1 起 = 家人），沿用 M1-01 的设计。界面上只出现“家人”，不出现任何密钥字样。
2. **添加家人**：“其他”页 → “添加家人”：称呼、关系（父亲 / 母亲 / 孩子 / 其他）、性别、出生日期（八字自动换算，M1-03）、居住城市（默认跟本人一样）。
3. **切换**：镜子页和问诊页顶部一排头像“我 / 爸爸 / 孩子”，点一下切换，当前是谁一眼可见；问诊发出前卡片上写清“替 爸爸 问诊”。
4. **数据隔离**：每位家人的病历、作业、打卡、舌象、调养方案分开存放，互不混淆；加密存储与备份覆盖全部家人（一次备份、一次恢复全家）。
5. **收发**：手机同时收本人和所有家人的消息（中继订阅覆盖全部家人的公钥，各自解密）。问诊包的档案里加 `managedBy`（代管人的称呼）。老师端显示“王老先生（王小明代管）”。老师签字病历和调养方案发给该家人的身份。
6. **康币：一家一本账**。账本仍是“老师 × 代管人（本人）”这一本，不为家人另开；每笔扣费在事件里加一个 `forMember`（家人称呼），账本页按家人筛选。签字病历的 `recordHash` 照常引用家人那份病历。
7. **邀请**：本人通过老师的邀请链接加入后，添加家人时自动把同一位老师加入该家人的“我的老师”。
8. **镜子与追问的年龄适配**：镜子页建议和问诊追问把年龄带进提示词：给孩子的建议不出现酒、浓茶、咖啡等；给老人的建议更关注起居安全（防跌倒、保暖）。
9. **模型**：家人共用本人接入的大模型（M1-21），不用各自接入。

不做的：家人自己用另一部手机登录同一账户；家人日后有了独立能力（例如孩子长大）把账户“移交”出去。两者以后再说。

## 验收用例

1. 添加“爸爸”和“孩子”两位家人，镜子页可切换三个人，各自的建议、作业互不出现在别人页面上。
2. 替爸爸问诊，老师端显示“爸爸的称呼（本人称呼代管）”；老师签字病历回到爸爸名下，作业进爸爸的作业页。
3. 清空浏览器后恢复，三个人的数据都回来。
4. 给孩子的镜子建议里不出现“酒、浓茶、咖啡”（用模拟模型和断言词表测）。
5. 界面可见文字仍不出现“密钥、助记词、公钥”。
6. 替爸爸和孩子各问诊一次、各扣费：账本只有一本，余额是两笔合计扣除后的结果，按家人筛选能分别看到各自那一笔。
