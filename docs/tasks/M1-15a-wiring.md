# M1-15a 串联：把各模块接成一条完整的问诊链路

- 状态：已派（DeepSeek，2026-10-17）
- 依赖：M1-05 至 M1-14b（均已完成）
- 白皮书依据：§5.2 全部 9 步

## 目标

各模块都已做好、各自有测试，但还没有接在一起。本卡把它们接通：学生发出问诊 → 老师收到、起草、签字 → 签字病历回到学生 → 作业进入提醒 → 康币扣费。

## 范围

1. **收件分发**：`app/src/core/inbox/`，一个 `createTransport` 实例，按信封 `type` 分给各模块：`consult.package` → 老师端问诊箱；`consult.attachment` → 老师端附件；`record.signed` → 学生端校验入库；`ledger.*` → `createLedgerSync().receive`。不认识的类型丢弃。
2. **照片单独发**：中继单条上限 2 MB，4 张 500 KB 的照片加上 base64 会超。改为：每张照片一条 `consult.attachment`（payload：`{ encounterId, ref, data: base64 }`），问诊包里只带 `AttachmentRef`。老师端按 `id` 和 `sha256` 核对，照片到齐才能起草；缺照片时界面显示“照片还在路上”。
3. **发送后提醒**：每次 `transport.send` 成功后调用 `notifyRecipient(pubkey)`（M1-08），失败不影响发送结果。
4. **学生端病历页**（新）：列出收到的签字病历，只显示 `verifySignedEncounter` 通过的；显示判断、方子、医嘱、作业；面诊病历主诉旁标“老师代录”（`intakeDisplayLabel`）。新版本（`supersedes`）显示为同一份病历的修订，旧版折叠保留。
5. **作业进提醒**：学生端收到签字病历后，把 `plan.homework` 写入 M1-13 的作业集合，`startsOn` 取收到当天。新版本病历替换同一 `encounter.id` 的旧作业。
6. **老师端问诊箱页**（新）：列出收到的问诊包，点开进入起草（M1-10）→ 审改签字（M1-11）。
7. **扣费入口**：老师签字页加一个可选“本次扣费 N 康币”，签字交还成功后用 `record` 记一笔 `charge`，`recordHash` 填签名事件 id。不填就不扣。
8. **首页**：按身份（老师 / 学生，M1 由设置里手动选）显示对应入口；已有的临时入口收进“设置”。
9. **加固（来自 #18 复核）**：
   - 老师端收到照片时**现场重算** sha256，与 `AttachmentRef` 不符就丢弃；
   - 老师端对问诊包里附带的历史病历逐份 `verifySignedEncounter`，签名人必须是本人，不通过的不给起草用；
   - 急症中断后，旧草稿在学生点“我已知晓并重新开始”时删除；
   - M1-05 接通后，`intake-outbox` 里的替身待发件改为真实发送，发送成功即删除。
10. 不改任何已合并模块的对外接口；确实要改的，在 PR 里单列说明。

不做的：端到端自动化测试和试点指标（M1-15b）；部署。

## 验收用例

1. 两个 `createTransport` 加内存中继替身（参照 `transport.test.ts`）：学生发出带 2 张照片的问诊包，老师端问诊箱出现这份问诊，照片到齐。
2. 老师起草、签字、填扣费 3：学生端病历页出现这份病历，作业出现在作业页，账本余额减 3，两端对账码相同。
3. 照片缺一张时老师端不能起草；补到后可以。
4. 篡改过的签字病历学生端不显示。
5. 每条消息发送后都调用了一次 `notifyRecipient`；`notifyRecipient` 抛错时发送仍算成功。
6. 375px 截图：学生病历页、老师问诊箱，放 `docs/screenshots/`。
