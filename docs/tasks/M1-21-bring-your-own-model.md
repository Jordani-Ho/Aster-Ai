# M1-21 自带模型：每个人的智能体接入自己的大模型

- 状态：已派（Codex，2026-10-17）
- 决策：发起人 2026-10-17 定（`team/decisions.md`）：从内测第一天起，每个用户都要接入自己的大模型，习惯从一开始养成；**必须接入才能使用**（1A）；内测期间保留家里的模型网关，**只作为接入后调用失败时的后备**（2A）。
- 依据：`docs/product/two-agents.md`（以老师为中心：这一步由每个用户自己完成，老师自己的也一样）

## 目标

第一次打开时，选完“老师 / 学生”，第二步就是“接入您的大模型”；接通之前，不能进入首页。

## 范围

1. **服务商清单** `app/src/core/llm/providers.json`（不是中医内容，不放 `domain/`）：DeepSeek、通义千问（阿里云百炼）、Kimi（月之暗面）、豆包（火山方舟）、以及“其他 OpenAI 兼容接口”。每家写：显示名、接口地址、默认模型名、是否需要额外字段（豆包要“接入点 ID”）、注册页面地址。模型名和地址**施工时逐家查官方文档核实**，在 PR 里贴出处和查证日期。
2. **接入页**：选一家 → 粘贴密钥（豆包再填接入点）→ 点“测试连接”（发一句很短的测试请求）→ 成功打勾进入首页；失败用一句大白话说明原因（密钥不对 / 余额不足 / 网络不通），不出现英文报错原文。每家旁边一个“怎么申请？”链接，打开对应的图文说明页 `app/public/help/<服务商>.html`（截图可以先空着，步骤文字要写全）。
3. **密钥保存**：只存在本机加密存储里，进入备份（备份本来就是加密的），换手机恢复后不用重填。设置里可以换服务商、换密钥。
4. **调用路径**（`core/llm`）：
   - 优先**从手机浏览器直接调用**该服务商；
   - 被该服务商拦截（跨域失败）时，经网关新增的 `/v1/proxy` 原样转发：网关只转发用户自己的密钥和请求，**不记录、不保存密钥和内容**，沿用现有的成员签名、请求体上限、限流、超时；
   - 逐家实测能否直接调用，结果写进 `core/llm/README.md` 的表格，**分“美国网络”和“国内网络”两列**：发起人在美国、老师和多数学生在国内，同一家服务商在两地的连通性可能不同；国内一列等国内成员加入时补测。
   - 国内大模型更新很快：模型名和地址不要写死在代码里，只放在 `providers.json`，以后改清单不用改代码。
5. **后备**：用户自己的模型调用失败（超时、余额不足、服务商故障）时，内测期间退回家里网关原来的上游模型，界面上显示一行小字“今天用的是备用模型，请检查您的模型账户”。网关配置里留一个开关，推广时关掉。
6. 老师端起草、改稿、学生端追问、镜子页建议，全部改走用户自己的模型。

不做的：本机模型（推广阶段再说）、按用量计费统计。

## 验收用例

1. 首次打开：选角色 → 接入页；未测试通过前进不了首页（Playwright 断言）。
2. 模拟服务商返回成功：打勾进入首页；返回 401 / 402 / 网络错误：分别显示三种大白话提示。
3. 模拟服务商跨域拦截：自动改走 `/v1/proxy`，请求成功；网关日志里没有密钥和内容。
4. 用户模型失败时退回后备模型，界面出现“备用模型”提示；后备开关关闭时，退回固定问句。
5. 清空浏览器后从备份恢复，不用重填密钥。
6. `providers.json` 每一家在 PR 里有官方文档出处和查证日期。
7. M1-15b 的 e2e 前置步骤加上接入（用模拟服务商）后仍全绿。
