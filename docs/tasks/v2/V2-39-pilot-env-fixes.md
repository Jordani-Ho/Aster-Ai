# V2-39 内测环境两处修补：网关限流按路由分开；正式的“重置老师登记”命令

- 状态：待派（**DeepSeek**；网关与部署脚本，属于工具）
- 依据：2026-10-28 内测准备实测（DeepSeek 报告）

## 一、网关限流按路由分开

**现象**：发起人手机第一次扫邀请，点“开始使用”只显示“暂时未能加入社区，请稍后重新打开邀请”。临时日志显示，同一公钥在一分钟内先发了一串推送请求（202），把每公钥 20 次 / 60 秒的额度吃光，后面的 `/invite/redeem` 和模型请求就被 429 拒掉。

**改法**：
1. 限流按路由分开计数，不再共用一个额度：
   - 进馆、登记类（`/invite/*`）：单独一个额度，够一个人反复重试（例如每公钥 10 次 / 60 秒）；
   - 推送类：单独一个额度，并查清首页为什么一打开就连发好几次推送请求，能合并的合并；
   - 模型转发：保持现在的额度。
   具体数值写在 `deploy/home/scripts/generate-gateway.mjs` 生成的配置里，网关 README 同步。
2. 学生端把 429 说清楚：“请求太频繁，请稍等一分钟再点”。不要和 401（时钟不准或身份不对）、5xx、断网混在“暂时未能加入社区”一句里；401 提示“请检查手机时间是否为自动设置”。

**验收**：
- 网关测试：同一公钥先发满推送额度，`/invite/redeem` 仍然 200。
- 网关测试：同一路由超过额度才 429，其他路由不受影响。
- 浏览器测试：模拟 429 / 401 时，邀请首屏显示对应的话。

## 二、正式的“重置老师登记”命令

**现象**：部署口令登记过一次老师后，就没有正式办法再生成老师登记口令。这次是 DeepSeek 手工挪文件完成的。

**改法**：新增 `deploy/home/reset-teacher-setup.sh`，把 DeepSeek 这次的步骤原样固化：
1. 把 `data/gateway/seed.json`、`data/setup/teacher-setup-code.txt`、`data/setup/teacher-setup.html`，以及 `data/backup/last/` 下同名的三个文件，**存在才移、不删**，统一移到 `data/backup/pre-reset-<时间>/`（必须连 `backup/last` 的一起移，否则 safeguard 会把旧种子恢复回来）。
2. 跑 `NO_VERIFY=1 ./update.sh`，等构建完成后再跑 `./verify.sh`。
3. 不动成员名单、不动中继数据、不重启 cloudflared。
4. 结束时打印：新的老师登记二维码在哪里；提醒“老师要用一个干净的浏览器身份（新的浏览器或新的浏览器配置），否则已开过馆的身份会直接进工作台”；提醒“只有最新登记的那位算老师”。
5. `docs/内测怎么开始.md` 加一小节“重新登记老师”。

**验收**：在部署测试（`e2e/deployment.test.mjs`）里加一条：登记过老师 → 跑重置 → 生成新口令且 `seed.usedFor` 为空 → 成员名单人数不变 → 旧文件在 `data/backup/pre-reset-*` 里。
