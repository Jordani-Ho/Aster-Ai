# V2-19 老师智能体：一事一议，只向签字学习，额度有上限

- 状态：待派（DeepSeek，接在 V2-18 之后）
- 依据：决策 2026-10-23；医纲第二·六、七条
- 原则：老师智能体替老师处理杂务，让老师把时间花在辨证施治上。它不是一个一直聊下去的对话框：每件事一次调用，只带这件事要用的材料，做完就忘。

## 范围

1. **一事一议（守住现状）**：起草、改稿、拆四诊、方案、记账，每件事各自一次模型调用，只带这一位学生、这一件事的材料；不把上一次调用的对话带进下一次。在 `core/drafting/README.md` 写明这一条，并加测试：连续起草两位学生，第二次请求里不出现第一位学生的任何内容。
2. **只向签字学**：`teacherCases` 只取老师签了字的病历（现状如此，加测试守住）。医案检索时，老师亲手改过的字段（来源不是 `ai_draft`、与草稿不同）优先；一字未改就签的病历只做“认可”统计，不进相似医案。改方的加减理由跟着医案一起给模型。具体用哪个字段区分“改过 / 原样确认”，按现有病历格式定，在 PR 里说明。
3. **额度上限**：每次调用前估算材料长度，设一个上限（数值放 `domain/` 配置，默认按常见模型的一半留余量）。超了按顺序减：先减旧病历（从最早的减），再减相似医案；**这次的问诊包和老师模板永远不减**。
4. **减了要说**：草稿上写一行，例如“旧病历只带了最近 2 次”“这次没参考相似医案”。不悄悄少带。
5. **模型报额度超限**：按第 3 条的顺序再减一轮重试；还不行就只用这次的问诊包起草，并标“没参考旧病历和医案”。流程不卡死，不把上游错误原文给老师看。

## 验收用例

1. 两位学生连续起草：第二次的模型请求里搜不到第一位学生的任何字段。
2. 合成一位有 30 次病历的学生：请求不超上限，最近的病历在、最早的被减掉，草稿上有“只带了最近 N 次”。
3. 一份老师改过方子、一份原样签字的医案：检索只给前者；后者只计入认可数。
4. 模拟模型返回额度超限：自动减材料重试成功；再模拟一次仍超：只用问诊包起草并带提示。
5. CI 三项全过。
