# V2-01 清场：删掉第一版的加密与保护层

- 状态：已派（DeepSeek，2026-10-18）
- 依据：`team/decisions.md` 2026-10-18 各条（隐私靠抽象化、不再加密；原图不留；保留期限由老师定；师生互为备份）

## 目标

把第一版里为“保护数据”而加的层整块拆掉，让代码明显变少、变直白。功能（问诊、起草、签字、作业、镜子、家人、自带模型）照常能用。

## 要删的

1. **本机存储加密**：`core/store` 里的 HKDF、AES-GCM、设备密钥包裹私钥等。改为普通 IndexedDB（键值存取），接口尽量不变，让上层不用大改。
2. **助记词与恢复**：生成、抄写核对、恢复页、“高级”入口。身份仍在本机自动生成并直接存放（不包裹）。
3. **中继备份**：`core/backup`、备份设置页、中继的 30078 备份槽与 `aster.identity` 槽（中继补丁里对应部分一并删除）。
4. **刷脸保护**：通行密钥与 PRF 相关全部代码和测试。
5. **诊毕即还的多步销毁**：签字后的“暂存 → 发送 → 销毁 → 写日志”流程简化为“签字 → 发送 → 成功提示”；记录的删除改由 V2-05 的保留期限统一处理。
6. **照片去 EXIF 流水线**：先保留压缩函数供 V2-03 使用，去 EXIF 的逐段剥离可以删掉（V2-03 之后原图根本不落地）。

## 要留的（我做的判断，不同意请在 PR 里提）

- **传递层的加密（NIP-17/44/59）先保留**：它只是调用现成库，对用户没有任何步骤，拆掉反而要改一大片收发代码。第二批再看是否简化。
- **签名**：老师签字、调养方案签名、代管证明保留——这是“签字只能老师本人”“他人不能冒充老师”两条底线，不是隐私保护。
- 急症提醒、模型接入、家人账户、坚持率等全部保留。

## 验收用例

1. `npm run typecheck && npm test && npm run build` 通过；e2e 去掉备份恢复、刷脸那几条后全绿。
2. 代码行数明显减少：在 PR 里贴出 `app/src` 删除前后的行数对比。
3. 界面上找不到“备份”“恢复”“助记词”“刷脸”任何入口。
4. 一次完整问诊（学生发 → 老师起草签字 → 学生收到病历和作业）照常走通。
