# V2-35 开馆准备不做硬性要求

- 状态：待派（**Codex**，接在 V2-34 之后）
- 依据：决策 2026-10-25（发起人：老师开馆不做硬性要求。药材库这些都不需要删除，他不填就行了——有很多老师有开方的能力却不备药材，有的主要以针灸为主、开方为辅。与学生建档不同：学生的基础信息是一个态度问题，老师的开馆准备不是）
- 原则：开馆准备是**建议**，不是门槛。没填的项，对应的功能按“没有”来走，不拦老师邀请学生，也不拦老师做事。

## 范围

1. **不再拦邀请**：`assertInviteReady` 不再因为基础工作缺项而抛错；老师随时可以发进馆邀请。
2. **缺项改成提示**：开馆引导和“我的馆”里照旧列出六项（模板、排班、邀约方式、药材库、保留期限、模型），没填的标“还没设，可以以后补”，不标红、不挡路。
3. **每项没填时怎么走**（逐项写测试）：
   - **模板**：用社区默认模板。
   - **排班**：不发面诊邀约，学生端不出现“请求时段”；其余照常。
   - **邀约方式**：按“过目”（老师点头才发），不自动发。
   - **药材库**：按“不备药材”；开方照常，不提示库存。
   - **保留期限**：用现在的默认值。
   - **模型**：用社区模型，或者只走规则、不调模型（以现有行为为准）。
4. **学生端不变**：进馆基础信息仍然必填（V2-23），这是学生的态度问题。

## 验收用例

1. 新老师六项都不填：能发进馆邀请，学生能进馆、能问诊，老师能签字。
2. 只填排班：面诊邀约正常，其余按默认。
3. 药材库不填：开方、签字都不提库存。
4. “我的馆”页面列出没填的项，文字是“还没设，可以以后补”，没有红色警告，也没有拦截弹窗。
5. 学生端进馆仍然要先填基础信息。
6. 只用合成数据；CI 三项全过。
