# V2-38 建馆按顺序来：六项逐项确认，再开馆接第一位面诊的学生

- 状态：待派（**Codex**）
- 依据：决策 2026-10-28（发起人：建馆的工作就是建药材库、排班等基础信息，然后才是开馆、接引第一位学生；第一位学生就是第一个面诊的人）。在决策 2026-10-25（开馆不做硬性要求，药材库等不填就行）的基础上收紧：**不要求填内容，但每一项老师都要亲自看过、点过头**。发起人补充（同日）：其它的都可能被略过，但“门面”怎么也得有——门面是硬性的。
- 起因：内测部署实测，建馆引导可以一项不碰就开馆，开馆后挂着一张“开馆准备可以以后补：六项都还没设”。顺序反了。

## 范围

0. **门面是硬性的**（建馆第 3 步）：馆名、学生怎么称呼老师、**一句介绍**三样都要填才能往下走（现在只要求前两样，“一句介绍”改为必填）；颜色有默认，但要在“学生看到的样子”预览里看过、点“就用这个名字”确认。开馆时再核一次门面是否完整。
1. **六项在“开馆”之前逐项走一遍**（建馆第 4 步）：模板、排班、邀约方式、药材库、保留期限、模型。一次只显示一项，按顺序往下走；每项都带好默认值：
   - 模板：社区默认的问诊、病历、施治、开方模板；
   - 排班：一套常见时段（例如周一到周五 9:00–12:00、14:00–17:00，每段 30 分钟、每段 1 位），老师所在城市和时区；
   - 邀约方式：老师过目后再发；请出名单天数不设；
   - 药材库：两个选项——“我自己备药，建药材库”或“**我不备药**”；
   - 保留期限：90 天；
   - 模型：已接的个人模型，或社区模型。
   老师要么改，要么点“**就这样**”确认，确认后自动进下一项；可以回头改。
2. **六项都确认过，“开馆”才亮。**“确认”不等于必须有内容：选“我不备药”就算药材库过了。没确认的那一项在列表里写“还没看”，不写“可以以后补”。
3. **老部署不拦**：已经开过馆的老师（有门面、学生或问诊）照旧直接进工作台；只在“我的馆 → 开馆准备”里看到没确认的项，不弹窗、不挡路。
4. **开馆后接的第一位学生，是来面诊的人。**第 5 步改为“请第一位来面诊的学生当面扫码”（链接仍可复制）。学生进馆、填好基础信息后，老师这边不只是跳回“今天”，而是出现“**某某已进馆 · 开始面诊**”，一点就进这位学生的面诊（沿用现有面诊流程，预选这位学生）；也可以“先不面诊，进工作台”。
5. **开馆后不再挂“开馆准备可以以后补”的单子。**六项以后改，都在“我的馆 → 开馆准备”。
6. 同步改 `docs/内测怎么开始.md` 第四节和 `docs/智能体架构.md` 第五节的说法。

## 验收用例

0. 建馆第 3 步：馆名、称呼、一句介绍任一为空，“就用这个名字”是灰的或给出提示，不能往下走。
1. 新老师：第 4 步六项依次出现；不点任何“就这样”时“开馆”是灰的；六项都点“就这样”（药材库选“我不备药”）后“开馆”亮。
2. 排班改一个时段后确认：保存的就是改后的；回到排班还能再改。
3. 开馆后“今天”页没有“开馆准备可以以后补”的单子。
4. 第一位学生当面扫码、填基础信息后，老师端出现“某某已进馆 · 开始面诊”，点了进入预选这位学生的面诊；点“先不面诊”进工作台。
5. 老部署（已有门面和学生）打开：直接进工作台，不被拦。
6. 生产包冒烟（`e2e/prod-smoke.browser.mjs`）照过。
7. 只用合成数据；CI 三项全过。
