# V2-25 预约：老师智能体主动请人来

- 状态：本地实现待审核（**Codex**，基线 `4e7c0ff`）
- 依据：决策 2026-10-23（预约以老师智能体主动邀约为主；2 小时不回就下一位，也可同时发几位，宁愿多几位同时到）；`docs/智能体架构.md` 第六节；旧版盘点第 5 节（能约过去的时间、不查排班节假日、无状态机是高危）
- 原则：预约是老师每天的主要工作。可约时段只有一个算法，创建、改期都用它。

## 范围

1. **可约时段**（`core/schedule` 的一个函数，唯一实现）：排班 ∩ 不是节假日 ∩ 还没过去（按老师时区，至少提前 2 小时，可配）∩ 该时段人数未满。
2. **老师智能体每天的邀约任务**（挂在 V2-21 骨架上）：
   - 挑人：距上次面诊或签字 ≥ 开馆时设的天数（默认 14 天），且没有未来预约、24 小时内没被邀约过。
   - 给每人发一个具体时段；同一时段可以同时发给几位，最多 = 该时段上限 + 1。
   - 邀约方式按开馆时选的：`auto` 直接发；`review` 列出“今天可以请这几位”，老师一键发。
3. **消息**（经中继，端到端加密，新增 envelope）：
   - `appointment.offer`：`{offerId, slotStart(带时区偏移), minutes, expiresAt(=发出后 2 小时)}`
   - `appointment.reply`：`{offerId, accept|decline}`
   - `appointment.confirmed`、`appointment.cancel`：`{offerId, reason?}`
   - 学生也可以主动发 `appointment.request`（想约哪几个时段），老师端按可约时段自动确认或回“这个时段约满了”。
4. **状态机**（非法转移一律拒绝）：`offered → accepted → confirmed → done | no_show | cancelled`；`offered → declined | expired`。同一个 `offerId` 重复收到只算一次。过期后学生才接受：回“这个时段已过期”，并给下一个可约时段。
5. **排班改动碰到已确认的预约**：保存前列出受影响的人，老师选“保留”或“取消并通知”；不能悄悄留着。
6. **老师“今天”页**：今天约了谁，按时间排；可以标“来了 / 没来”。
7. **学生端**：收到邀约有倒计时；学生智能体催他回复（督促规则见 V2-27）。时间按老师的时区显示，并写明城市。

## 输入校验与边界（每条都要有测试）

- 过去的时段、节假日、排班外的时段、人数已满：都不能被约（不管是邀约、请求还是改期）。
- 跨夏令时那一天、师生不在同一时区：显示和计算都对。
- 过期回复、重复回复、对已取消预约再确认：被拒。
- 同时发给几位：确认人数到上限后，其余人的接受回“约满了”并给下一个时段。

## 验收用例

1. 老师按默认排班开馆，有三位学生超过 14 天没来：`review` 模式下列出三人；一键后三人各收到一个时段。
2. 学生 2 小时不回：邀约过期，时段给下一位。
3. 同一时段上限 3 位、发给 4 位、4 位都接受：前 3 位确认，第 4 位收到“约满了”和下一个时段。
4. 上面每条边界各一条用例。
5. 老师把周三改成休息，周三已有 2 位确认：保存前列出 2 人；选“取消并通知”后两人收到取消。
6. 两台手机跑真实中继 e2e：邀约 → 接受 → 确认 → 老师“今天”页出现。
7. CI 三项全过。
