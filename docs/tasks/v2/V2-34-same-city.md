# V2-34 面诊邀约只限同城；居住城市随时可改

- 状态：待派（**Codex**，接在 V2-25b、V2-27 之后）
- 依据：决策 2026-10-25（发起人：远程的学生一般不会预约，远在美国不可能赴约，所以老师发起的预约只限于同城学生；学生的现居住城市是可改的——回国探亲改成国内，回美国再改回来）
- 原则：同城与否只看“学生现在住哪”和“老师在哪”两个城市名，不猜、不定位；城市不明就不约面诊。

## 范围

1. **同城的判定**：学生当前居住城市与老师本机档案城市同名，才算同城。任一方没填城市，就按异地处理。
2. **老师端邀约只发同城**：
   - V2-25 的自动邀约与手动邀约，候选名单只取同城学生；异地学生不出现在邀约候选里。
   - 学生名单上给异地学生标“异地 · 远程问诊”，老师一眼能分清。
   - 改排班时，“受影响的学生”只会是同城的（异地本来就约不上）。
3. **学生端只有同城才能请求面诊**：V2-25b 的“请求时段”入口只在同城时出现；异地时这里改为“远程问诊”入口。
4. **居住城市改了，老师要知道**：
   - 学生在“基础信息”或“我的时间”里改居住城市，学生端给自己的每位老师发一条带签名的城市更新（只有城市名，端到端加密）；老师端收到后更新这位学生的城市，并据此重算同城与否。
   - 改城市不需要确认（出生信息才需要）；也不进 `basics-history`。
   - 改成异地后，这位学生已确认、还没到时间的面诊：学生端提示“你现在不在老师所在城市，这次面诊要保留吗？”，选“取消”就走 V2-25b 的取消并通知老师；选“保留”照旧。不自动取消。
5. **复诊督促分两种说法**（接 V2-27 的固定话术）：同城用现在的“去约个时间”；异地改用“发一次远程问诊”这类话术，新增话术键（例如 `revisit.remote.first` / `again` / `daily`），同样过禁用词检查、只填真实数据。

## 不做

- 不做定位、不读 IP、不按时区推断城市。
- 不改远程问诊本身的流程。
- 老师自定话术、节气保养邀约：只记为邀约模块以后的可能性，本卡不做（决策 2026-10-25）。

## 验收用例

1. 老师在广州；学生 A 住广州、学生 B 住旧金山：自动邀约只发给 A；学生名单上 B 标“异地 · 远程问诊”。
2. B 把居住城市改成广州：老师端收到更新，B 进入邀约候选；B 学生端出现“请求时段”入口。
3. A 已确认下周面诊后把城市改成旧金山：A 学生端出现保留/取消提示；选取消，老师端收到取消通知，时段放回去。
4. 任一方城市为空：不发面诊邀约，学生端不出现请求入口。
5. 复诊督促：同城学生收到“去约个时间”，异地学生收到远程问诊的说法；两组话术都过禁用词测试。
6. 两台手机真实中继 e2e：学生改城市 → 老师端名单标记随之变化。
7. 只用合成数据；CI 三项全过。
