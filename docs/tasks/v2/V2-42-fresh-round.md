# V2-42 内测每一轮从头再来：一条命令清场，手机上一个按钮清空

- 状态：待派（**DeepSeek**；部署脚本与内测专用按钮，属于工具）
- 依据：决策 2026-10-29（发起人：每次修改之后，都应该从头〔建馆〕再来）；内测实测——老师名单里留着测试身份、旧草稿、重新登记后丢了模型设置，问题混在一起分不清
- 原则：机器每次合并都从头测（CI 已经这样）；人每一轮内测也从头走，不在旧数据上接着试。不删任何东西，只挪到备份。

## 一轮内测怎么走

1. 内测环境更新到新版本（`update.sh`）。
2. 部署电脑上跑 `./fresh-round.sh`（本卡新增）：清场、生成新口令、打开新的老师浏览器。
3. 两台手机各点一次「清空这台设备上的知衡」（本卡新增），回到第一次打开的样子。
4. 发起人从建馆第 1 步开始，按《内测怎么开始》第六节逐项试。

## 一、`deploy/home/fresh-round.sh`

1. 把上一轮的登记和名单**存在才移、不删**地移到 `data/backup/fresh-<时间>/`：
   - 老师登记凭据（同 `reset-teacher-setup.sh` 的六份）；
   - 成员名单 `data/gateway/members.json`（含老师、核心成员），以及 `data/backup/last/` 里的同名文件。
2. 不动中继数据（发给旧身份的加密包裹没人能读，30 天后自己过期），不重启 cloudflared，网址不变。
3. 跑 `update.sh`（V2-39 之后它会等网页就绪再验收）。`verify.sh` 会照旧把验收自测成员补回名单。
4. 老师浏览器：新建一个空的 Chrome 配置目录（`知衡内测-老师-<时间>`），把桌面快捷方式「知衡内测-老师Chrome」改成指向它，并直接打开新的老师登记扫码页。旧配置目录不删。
5. 最后打印：新口令位置、备份目录、「两台手机各点一次清空」的提示。
6. 核心成员也随名单清掉：发起人这一轮要按第六节第 14 项重新登记核心成员。

`reset-teacher-setup.sh` 保留（只换老师、不清名单时用），顺手把它最后那次 `verify.sh` 改成交给 `update.sh` 等就绪后再跑（#109 审核时留下的问题）。

## 二、手机上「清空这台设备上的知衡」

- 位置：学生端和老师端的「设置」最底下。
- **只在内测部署里出现**：部署脚本构建网页时打开一个内测开关；正式版本里没有这个按钮。
- 点了以后先说清楚：「会删掉这台设备上知衡的全部资料（身份、病历、照片、设置），删了找不回。」要输入「清空」两个字才执行。
- 执行：删掉本站的 IndexedDB 和本地存储，注销后台脚本，回到第一次打开的样子。
- 不发任何消息，不碰网关和中继。

## 边界（每条都要有测试）

- `fresh-round.sh`：跑完后种子没有 `usedFor`、口令是新的、名单里只剩验收自测成员；旧文件都在 `fresh-<时间>/` 里；`data/` 里没有文件被删。
- 连跑两次：第二次也能成功，备份目录不互相覆盖。
- 清空按钮：内测开关关闭时页面上没有这个按钮；没输「清空」不执行；执行后刷新回到第一次打开的页面。

## 验收用例

1. 部署测试（假 docker、假 curl）覆盖上面三条脚本边界。
2. 浏览器用例：内测开关打开时，学生端和老师端设置里有这个按钮；输入「清空」后 IndexedDB 为空，页面回到首次打开。
3. 《内测怎么开始》：第三节第 4 项改写成「每一轮从头再来」，写清上面一轮的四步；第五节写清手机怎么清空。
4. 只用合成数据；CI 三项全过。
