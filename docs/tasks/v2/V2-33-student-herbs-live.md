# V2-33 学生药材库：有数量、老师开方能直接调用、学生智能体来管

- 状态：待派（**Codex**，接在 V2-24 之后）
- 依据：决策 2026-10-25（学生药材库也要有具体数据，老师开方时可以直接调用；学生药材库由学生智能体管理）。本卡取代 V2-24 里“只发药名和够 / 快没了、不发数量”的口径。
- 发起人 2026-10-25 补充：①只有需要远程诊疗的学生才需要建药材库；库存变化不用马上同步，只在远程诊疗时被调用，和病历一起管理。②家人不用另建药材库，一家一个库。③药材是耗材，不属于隐私信息。
- 原则：库存数据在学生本机；远程问诊时随问诊包发给这位老师，和这次病历一起保存，不进任何中心。

## 范围

1. **只在远程问诊时带上数量**：学生药材库的药名、数量、单位，在远程问诊时作为“家里的药材”随问诊包发给老师（替代 V2-24 的“够 / 快没了”）。平时库存变化不同步，不新增单独的同步消息。
   - 和病历一起管理：老师端把这份快照存在这次问诊/病历旁边，开方时调用；之后的病历各带各的那一份。
   - 药材是耗材，不是隐私：远程问诊时默认带上，不用学生逐味勾选；学生库为空就不带。
   - 一家一个库：家人问诊用同一个库（代管人的），不再按家人分开。
   - 只有远程问诊的学生需要建库：学生端“药材库”入口放在远程问诊相关的位置，当面看诊的学生不必理会。
2. **老师开方直接调用**：
   - 老师审远程问诊时，能看到这次问诊带来的学生家里的药材和数量。
   - 老师智能体起草方子时，把学生家里的库存当作材料：每味药标“家里有 X 克，够 N 剂 / 家里不够，差 X 克 / 要另抓”。只标出来，不改方子（方子由老师定）。
   - 开方签字后，在发给学生的方子上写明哪几味要另抓、各要多少。
3. **学生智能体来管**（挂在 V2-21 骨架上的学生端任务）：
   - 学生点“煎了一剂”，按方子自动扣自己的库存（V2-24 已有，这里改成由智能体任务执行；不同步给老师，下次远程问诊时自然带上最新数量）。
   - 快用完（低于警戒线）或按当前方子不够下一剂时，提醒学生补货，并列出要补哪几味、多少。
   - 老师签发了新方子：对照家里库存，告诉学生“这几味家里有，这几味要去抓”。
4. **老版本兼容**：老师端收到只有“够 / 快没了”的旧格式也照常显示。

## 输入校验与边界（每条都要有测试）

- 快照里的数量、单位与 V2-24 同一套校验；格式不对整份丢弃，不影响问诊。
- 单位换算按老师确认的钱/两配置；学生那边没确认换算时，只按克、片、枚、个计。
- 一剂不够：标“差 X 克”，不四舍五入成“够”。

## 验收用例

1. 学生入库 300 克黄芪后发远程问诊：老师审方页显示“黄芪 300 克”；之前没有问诊时老师端看不到。
2. 老师方子里黄芪 30 克、当归 10 克，学生家里黄芪 300 克、无当归：起草页显示“黄芪 家里有 300 克，够 10 剂；当归 要另抓”；签字后学生收到的方子写明“当归要另抓 10 克”。
3. 学生点“煎了一剂”：本机库存自动扣减；老师端不变，下次远程问诊带上新数量。
4. 学生黄芪剩 20 克、方子每剂 30 克：学生端提醒“黄芪不够下一剂，差 10 克”。
5. 家人代管：替妈妈问诊时带的是同一个家里的药材库。
6. 两台手机真实中继 e2e：学生入库 → 远程问诊 → 老师审方页看到数量；CI 三项全过。
