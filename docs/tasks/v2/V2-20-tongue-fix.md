# V2-20 舌象修复：镜子显示完整，拍摄少失败、失败说得清

- 状态：待派（DeepSeek）
- 依据：`team/founder-selftest-log-2026-10-23.md` 第二节（排查结论与 8 条建议）；决策 2026-10-23
- 原则：只修舌象这一条线；不改病历格式。原图仍是当场清掉（医纲第二·四条）。

## 范围

1. **镜子显示完整**：`.nl-mirror-frame` 里的裁剪图改成 `object-fit: contain`，整条舌头都看得见；高度可以放宽，不再固定 80px，但卡片不要被撑得太高。
2. **送模型前先规范图片**：舌象这一路也走 `processPhoto`，长边 ≤1600、重新编码成 JPEG、去掉 EXIF。这样 `image/jpg`、大小写、空 type、大图都不用再特殊处理。如果浏览器解不开（比如某些 HEIC），明确提示：“这张照片的格式手机浏览器打不开，请用相机直接拍，或在相机设置里选‘兼容性最佳’。”
3. **模型回复容错**：去掉 ```json 围栏和前后说明再解析；舌头框接受 0–1 归一化和 0–1000 两种（大于 1 就按 1000 换算），多出来的字段忽略。其他格式仍然拒绝。
4. **门槛按实际拍法定**：去掉“面积 ≥5%”（提示词和解析器里都去掉）。改成：裁剪后舌头短边 ≥160 像素才算看清；不够就提示“靠近一点再拍”。具体像素值放在 `domain/tcm/tongue-features.json`。
5. **失败分档说清楚**，每一档一句话：
   - 照片格式打不开（见第 2 条）；
   - 没拍到舌头 / 太远（见第 4 条）；
   - 模型暂时连不上（网络、超时、5xx）：自动重试一次，还不行再提示“稍后再拍”；
   - 模型账户有问题（401/402/429）：提示“看舌象的模型账户需要检查（额度或密钥）”，老师端和学生端各自去自己的设置。
6. **只记失败类别**：本机记录每次失败属于哪一档（不存照片，不存模型原文），给以后排查用。
7. **拍照页加一句构图提示**：自然光、关美颜、舌头放松伸出、手机离脸一拃左右。

## 验收用例

1. 375 / 412 / 448 三种宽度下，照镜子里的裁剪图可见比例 100%（e2e 断言 img 实际显示区域等于图片宽高比）。
2. `image/jpg`、`IMAGE/JPEG`、空 type、长边 6000 的合成图：都能送出，送出去的是 ≤1600 的 JPEG。
3. 模型回复带 json 代码围栏、带一句说明、框是 0–1000 坐标、多一个字段：都能解析；纯乱码仍然提示失败。
4. 合成图里舌头占画面 1%（正常持机距离）但裁剪短边 ≥160 像素：通过；裁剪短边 100 像素：提示靠近。
5. 模拟 503 一次后成功：用户无感；连续 503：提示稍后再拍；401：提示检查模型账户。
6. 机型自适应：iPhone 15 Pro（iOS Safari，393×852，DPR 3，相机默认 HEIC）和华为 Mate 40 Pro（448×924）两种都跑一遍 1–5；其他宽度不写死。
7. 只用合成图；CI 三项全过。
