# V2-07 换手机：靠师生互认找回身份

- 状态：已派（DeepSeek，接在 V2-06 之后）
- 依赖：V2-05（互为备份）
- 依据：第二版不要助记词、不要刷脸（决策 2026-10-18）；“师生互为备份”。技术合伙人 2026-10-18 定。

## 思路

清空浏览器后身份也没了，不再靠用户抄写任何东西，而是靠“认识你的人”认回来：学生由老师认，老师由学生认。认回后，对方把保留期内的记录自动发回（V2-05 已有）。

## 范围

1. **学生换手机**：学生打开老师的邀请链接，生成新身份，填称呼后发一条“我是原来的某某”的请求。老师端看到一句话提示“小王说他换了手机，是他吗？”，老师点“是”（老师认得自己的学生，可以电话或当面确认）。老师端把名单里旧公钥换成新公钥，然后自动回发保留期内的记录；病历仍是原签名，学生端按“老师确认过的换机关系”接受旧公钥对应的记录。
2. **老师换手机**：老师生成新身份后，向名下学生发“换机通知”。学生端提示“阿慈老师说她换了手机，是她吗？”，学生点“是”后，把老师白名单换成新公钥，并把手里的记录自动回发。**学生没点“是”之前，新公钥签的任何东西都不接受**——这守住“他人不能冒充老师”的底线。
3. 家人账户随管理人一起认回，不单独确认。
4. 任何一方点“不是”，请求作废，不做任何改动。

## 验收用例

1. 学生清空浏览器 → 用邀请链接进入 → 老师点“是” → 学生收回保留期内的病历，旧病历仍能验签。
2. 老师清空浏览器 → 两位学生各点“是” → 老师收回两人的记录；第三位学生没点，新公钥发来的方案被拒。
3. 冒充者用新身份自称“小王”，老师点“不是”，名单不变、什么都不发。
