# V2-21 智能体骨架：角色、记忆、主动、守线

- 状态：待派（**Codex**）
- 依据：`docs/智能体架构.md`（含蓝图）；决策 2026-10-23“两端的核心是智能体，由 Codex 或技术合伙人写”；V2-19 一事一议
- 原则：智能体本身只有四件事；其余都是工具。这张卡只搭骨架、把现有的两件事接进来，不加新功能。后面 V2-22～V2-27 的“主动”任务都挂在这副骨架上。

## 范围

新建 `app/src/core/agent/`（与领域无关；中医内容仍在 `domain/tcm/`、`prompts/`）：

1. **角色 `role.ts`**：从本机设置读出这个智能体是谁、替谁做事、按什么做事。
   - 老师智能体：老师公钥、基础模板（V2-22 补全）、邀约方式（`auto` / `review`，V2-22 补全）。
   - 学生智能体：学生公钥、当前老师、本人作息（V2-23 补全）。
   - 缺的项给明确默认值，并能说出“还差哪几项”。
2. **任务登记 `tasks.ts`**：每件“主动”的事登记成一个任务：
   `{ id, side: 'teacher'|'student', trigger, gather(), run(), confirm: 'human'|'template', deliver() }`
   - `trigger`：打开应用时 / 某个时辰 / 收到某类消息 / 人点了一下。
   - `gather()` 只取这件事要的材料，受 V2-19 的额度上限约束。
   - `run()` 能用规则就不调模型。
   - `confirm`：`human` 必须真人按；`template` 表示按基础模板允许自动发出。
3. **执行器 `runner.ts`**（一事一议）：
   - 一次只跑一个任务，不带上一次的对话。
   - **幂等**：同一任务、同一对象、同一天只产出一次（键：`taskId + targetId + localDay`）；重复触发直接返回上次结果。
   - 失败只记类别（不存原文、不存模型回复），沿用 V2-20 失败分档的写法。
   - 产出先成草稿；`confirm:'human'` 的草稿进“等您确认”，不自动发。
4. **守线 `guard.ts`**（代码能查的都写成代码）：
   - 签字、入账、退款不经执行器，路径上不调模型（加测试：这三条路径的模块不 import `core/agent`）。
   - 智能体只能给有师生关系的公钥发消息。
   - 智能体不能写 `source:'teacher'` 的字段。
   - 同一任务对同一个人的消息，两次之间至少隔一个时辰（防程序出错连发；不是督促频率上限）。
5. **触发的现实约束**：网页应用在后台不能自己跑。所以“每天的事”在**打开应用时**补跑当天没跑的；另外通过已有的网页推送（`core/push`）在约定时辰提醒“打开看看”。写进 README。
6. **接进现有两件事**（行为不变，只是改为经执行器跑）：老师端“起草病历”（`drafting`）、学生端“今日镜子建议”（`mirror`）。

## 验收用例

1. 同一任务同一天触发三次：只产出一次，后两次返回同一结果。
2. 连续跑两位学生的同一任务：第二次的材料和模型请求里没有第一位的任何内容。
3. `confirm:'human'` 的任务：不点确认就没有任何消息发出。
4. 守线：给非本馆学生发消息被拒；尝试写 `source:'teacher'` 被拒；同一任务一个时辰内对同一人第二次发送被拒。
5. 签字、入账、退款模块不 import `core/agent`（测试里静态检查）。
6. 起草病历和镜子建议经执行器跑，原有测试全过；CI 三项全过。
