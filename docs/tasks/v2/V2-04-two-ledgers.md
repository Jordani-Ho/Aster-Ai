# V2-04 两本账：钱账与康币账

- 状态：已提交，待 Claude 审核（Codex，2026-10-18）
- 依据：决策 2026-10-18 康币各条（时间 × 效果、先打地基、两本账、老师一句话记账）

## 范围

1. **钱账（实）**：在第一版账本基础上改名、简化。事件：充值、赠送（赠送的是钱）、扣费、退款；金额用老师所在地的货币，定价全凭老师。**老师一句话记账**：老师对智能体说“今天收到小王 100 块，帮他充进去，再送 20”，智能体解析成事件草稿，老师点一下确认才入账（确认这一步不调用模型）。学生端看得到自己在这位老师那里的余额。一家一本账（沿用代管）。
2. **康币账（虚）**：单位“刻”。事件：
   - `create`：坚持 × 效果产生（由规则表计算）；
   - `flow`：占用老师时间，按刻从学生流向老师；
   - `decline`：健康变差时减少。
   与钱账完全分开，互不换算。
3. **规则表**（`domain/tcm/kangbi-rules.json`）：效果怎么算（老师判断、本人感受、智能体实测三方各占多少）、坚持一天折多少刻、变差扣多少、一次问诊占几刻、每日上限……全部写成配置，初始值保守、可改。代码里不写任何具体数字。
4. **观察接口**：每本账对外只提供汇总（人数、总量、流向分布），不提供个人明细；第二批的“观察”模块调用它。
5. **对外的口**：康币账上留一个空的“对外连接”接口（类型定义 + 不实现），为将来与法币或代币连接留位置。

## 验收用例

1. 老师说“收到小王 100，送 20”：生成两条草稿，确认后余额 120；不确认不入账。
2. 改规则表里“坚持一天折多少刻”，不改代码，产生的康币随之变化。
3. 一段时间坚持但效果为零：康币不增加。
4. 观察接口的输出里没有任何个人名字或公钥。
5. 钱账与康币账之间没有任何换算函数（测试断言）。
