# V2-30 体态工具：骨架识别与老师自己的指标

- 状态：待派（**DeepSeek**，工具类）
- 依据：决策 2026-10-24（小黄老师观察学生的整体骨骼架构、分析失衡的节点和原因，需要视频与三维结构方面的工具；他有自己的一套指标体系，正是智能体要学的；他馆里电脑和摄像头够用）；`docs/智能体架构.md` 第八节（工具只管数据和规则，不自己判断）；医纲第二·四条（原始材料用完即毁）
- 原则：这是一件**工具**。它只负责“把人变成骨架、按老师定的公式算数”，不下结论；结论是老师的。指标不由我们定，由老师定。

## 范围

新建 `app/src/core/posture/`，并在 `domain/` 下放默认指标示例。

1. **两种输入，同一种输出**
   - **手机**：学生（或家人账户）拍正面、侧面各一张，或一段 ≤15 秒的视频。在浏览器里做单人骨骼识别，得到每个关键点的坐标。识别模型文件**随部署一起提供**（放在自己的服务器上，不从国外 CDN 下载，国内要能用）。这是新增依赖（B 类），批准；版本写死。
   - **工作室**：老师馆里用 FreeMoCap 多机位捕捉，导出骨骼数据文件，在老师端“导入骨架”。FreeMoCap 是 AGPL 许可，**不把它的代码放进我们的仓库**，只读它导出的文件；先查清它当前版本导出的文件格式，写进 README，用合成样例做测试。
   - 输出统一为：`{ 关键点名 → 坐标（2D 或 3D）, 来源: phone|studio, 视角: front|side|video, 时间 }`。
2. **用完即毁**：照片和视频识别完当场从应用里清掉，只留关键点和一张骨架示意图（线条图，认不出是谁）。
3. **老师自己的指标**
   - 老师在“我的馆 → 模板”里多一类“体态指标”：每条指标 = 名称 + 公式 + 单位，公式只能用关键点坐标做几种运算（两点高低差、两点距离、三点夹角、左右对称差、偏离中线）。
   - 我们只给几条**示例**（两肩高低差、骨盆倾斜、头前伸、脊柱偏离中线），老师可以改、删、加。不内置任何“正常范围”或诊断。
4. **进病历**：骨架和指标值作为一份“体态记录”附在问诊包或面诊记录里（病历新增可选字段 `postures`，B 类，批准；老版本没有这个字段照常收）。老师端显示骨架示意图、各指标值、和上次的对比。
5. **给智能体留口子**：老师在体态记录上写的判断（哪个节点失衡、为什么），随签字病历保存。让老师智能体从这些签字记录里学老师的指标体系，是以后一张智能体卡的事（Codex），本卡不做。

## 输入校验与边界（每条都要有测试）

- 照片、视频格式和大小沿用 V2-20 的规范化与分档；视频超时长拒绝并说明。
- 画面里没有人或不止一个人：明确提示，不猜。
- 关键点置信度低的，标“看不清”，不参与计算；公式用到看不清的点时，这条指标显示“这次算不出”，不编数。
- 公式只允许白名单运算和已知关键点名；写错时说清楚错在哪。
- FreeMoCap 导入：文件格式不对、关键点缺失、帧数为零，都拒绝并说明。

## 验收用例

1. 合成的正面、侧面人体图：识别出关键点，四条示例指标都有值；照片在应用里查不到。
2. 老师新加一条指标“左右膝高低差”：下次记录自动算出。
3. 合成 FreeMoCap 导出文件：导入后与手机输入用同一套指标、同一张骨架图显示。
4. 同一位学生两次记录：老师端显示每条指标的前后对比。
5. 识别模型文件从本部署地址加载，不请求国外域名（e2e 断言网络请求）。
6. iPhone 15 Pro 与华为两种宽度截图；只用合成图；CI 三项全过。
