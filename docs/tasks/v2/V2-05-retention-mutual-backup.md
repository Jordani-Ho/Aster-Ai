# V2-05 保留期限由老师定；师生互为备份

- 状态：已派（DeepSeek，2026-10-18，接在 V2-02 之后）
- 依据：决策 2026-10-18“保留多久由老师定”“师生互为备份”

## 范围

0. **先补老师端的医案（V2-01 遗留）**：V2-01 去掉多步销毁时，连老师端的记录也一起不写了（`signed-encounters`、`case-book` 现在都没有写入者）。本卡第一步：老师签字发送成功后（远程和面诊两条路径），把**完整签名病历**存进一个集合 `teacher-records`。学生索引（面诊选“已有学生”）、起草时的医案检索、改方的 `previousOf`、康币扣费的 `recordHash`，都从这一个集合读；`case-book`、`signed-encounters` 并入后删掉。顺手更新 `core/record`、`core/store`、`core/ledger`、`core/transport` 几份 README 里过时的说法（`pending-handover`、备份、“不留病历内容”）。
1. **保留期限**：老师在设置里定“记录保留多久”（默认 90 天，可选 30 天到 3 年）。这个设置随调养方案发给该老师的学生，学生端按老师的设置滚动删除自己的镜子记录、问诊卡片、作业打卡；老师端按同一设置删除医案。
2. **长期保留的只有沉淀**：调养方案（最新一版）、作业规则、老师的思想指纹（改稿习惯摘要），不受保留期限影响。
3. **互为备份**：学生换手机后，向老师请求“把我的记录发回来”；老师端自动回发保留期限内的该学生记录（老师不用操作）。老师换手机时，向名下学生逐个请求，学生端自动回发。
4. 删除每天在打开应用时执行一次，不需要后台任务。

## 验收用例

0. 一次远程问诊和一次面诊签字后，老师端 `teacher-records` 各有一份完整病历；起草检索能搜到上一份；改方后 `previousOf` 指向旧版；`case-book`、`signed-encounters` 在代码里搜不到（README 除外不算，README 也要改掉）。
1. 老师设 30 天：第 31 天打开应用，31 天前的记录在两端都不见了；调养方案还在。
2. 学生清空浏览器后，打开老师的邀请链接重新进入，自动收回保留期内的记录。
3. 老师清空浏览器后，名下两位学生的记录被自动收回。
