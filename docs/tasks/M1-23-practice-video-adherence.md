# M1-23 练习视频与坚持率：帮学生把动作练成习惯

- 状态：待派（排在 M1-22 之后；视频部分技术难度最高，派给 Codex）
- 依据：发起人 2026-10-17 描述的一位老师的做法：学生当面去学，最后一天老师拍下学生自己练习的视频带回家；回家后动作会慢慢走样，需要远程回看纠正。习惯很难改，所以他更愿意带孩子（`docs/product/two-agents.md`“平衡”与“坚持”）：老师为学生设计一套动作，学生在老师处学会；最后一天老师**拍下学生自己练习的视频**，让学生带回家对照练；有疑问时微信视频即时指导。病好得快，难在一周之后能否坚持。

## 目标

让“学生自己的练习视频”成为作业的一部分，让智能体每天帮老师盯着学生坚持，让老师一眼看出谁快坚持不住了。

## 范围

1. **拍练习视频**（老师端面诊工作台）：在某条作业上点“拍练习视频”。**用手机系统自带的相机录制**（`<input type="file" accept="video/*" capture>`），不用浏览器内录制：系统相机出来的是各家都能播放的 MP4（H.264），而浏览器内录制在苹果和安卓上格式不一，互相可能放不了。也可以从相册选一段。
   - 压缩：浏览器支持 WebCodecs 时，在本机转成 720p、约 1.5Mbps 的 MP4；不支持（例如部分华为浏览器、微信内置浏览器）时，原样上传，但单段超过 60MB 就提示“请剪短一点”。
   - 单段不超过 3 分钟。参考实例（发起人提供的一段真实动作视频，未入库）：142 秒、544×960、H.264 High + AAC、约 1.5Mbps、27.5MB，说明微信转过的视频本身就在目标范围内，压缩不是必需步骤。视频里老师边做边讲，**声音同样重要**，慢放时保留声音。视频随签字病历交还给学生，老师端照常诊毕即还、不留。
2. **传输：加密文件存放，不塞进中继消息。** 视频动辄十几 MB，切成几十条中继消息既慢又容易丢。改为：
   - 在本机用一次性随机密钥（AES-GCM）加密整段视频，上传到**老师节点上的文件存放服务**（优先采用现成开源的 Blossom 媒体服务器，按 Nostr 的 Blossom 规范；评估后不合适，再在网关里实现最小版本：按 SHA-256 存取、成员签名鉴权、单文件上限、30 天自动过期、只存密文）；
   - 经中继只发一条小消息：文件的 SHA-256、大小和解密密钥（这条消息本身是端到端加密的）；
   - 学生端下载、校验、解密后存在本机；下载失败显示“视频还在路上”，可重试。
   - 部署：`deploy/home/compose.yaml` 增加这个服务，经同一条 Cloudflare 隧道访问；访问日志照样关闭。
2c. **一人一套，不做共享动作库**（发起人 2026-10-17 更正）：动作是老师为每位学生单独设计的，同样的动作换一个人就无效，原因各不相同。所以每段视频只属于那一位学生，不能转给别人，也不做“通用动作库”。视频可以是老师为这位学生录的示范，也可以是老师拍这位学生自己练习的样子。
3. **学生端作业**：作业卡片上显示“对照视频”，点开全屏播放，可以循环、慢放（0.5 倍）。视频加密存在本机。中继备份不含视频（太大），“导出备份文件”含视频；换手机时提示“视频请从备份文件恢复，或请老师重发”。
4. **我练给老师看：防止“走样”**（发起人 2026-10-17 更正：这是核心，不是可选项）：学生当面学会、回到家里自己练，时间一长动作一定会走样，所以远程回看是必需的。
   - 学生在作业上点“录一段我的练习”，发给老师。
   - **并排对照**：老师打开时，左边是当初拍的视频，右边是今天这段，两段同步播放，一眼就能看出哪里变了。老师回一句文字或一段语音。
   - 学生自己也能用并排对照：练之前先看一遍，自己发现走样。
   - 每周镜子页提醒一次“录一段给老师看看有没有走样”，可以跳过。
   - 即时的视频指导仍然用微信，不在本产品里重做。
4c. **把动作嵌进已有的生活习惯**（发起人 2026-10-17 补充的实例：老师按一位学生自己的习惯设计动作，比如教她“怎么拖地”来纠正问题，一个月后明显改善）：
   - 作业的时间安排新增一种 `{ kind: 'habit'; anchor: string }`，`anchor` 是学生已有的日常习惯，例如“起床后”“刷牙时”“拖地时”“通勤路上”“睡前”。
   - 这类作业不按钟点提醒，而是出现在镜子页“今天做这些事的时候，记得……”一栏，做完点一下打卡。
   - 需要同步改：病历格式 `docs/schemas/encounter.md` 与 `app/src/core/record/types.ts`（由施工者在本卡 PR 里一起改，技术合伙人审），M1-10 起草校验、M1-13 排程与打卡、M1-20 改稿提示词。
5. **坚持率**：
   - 学生端：镜子页的作业旁显示“已连续练习 N 天”；连续漏练 2 天时，第二天镜子页的建议里多一条温和的提醒（不说教，沿用 M1-19 的口吻）。
   - 老师端：“今天”页列出本周坚持率低于一半的学生，排在前面；远程工作台每位学生旁显示本周练习天数。
   - 试点指标导出（M1-15b）加第五列“作业坚持率”。
6. 家人账户（M1-22）同样适用：家长替孩子看对照视频、打卡。

不做的：应用内实时视频通话（用微信）；动作识别与自动纠错。

## 验收用例

1. 老师在面诊时给作业拍一段 60 秒视频，签字交还后，学生端作业里能播放；老师端查不到这段视频。
2. 一段 20MB 的合成 MP4 加密上传、经中继发出密钥：学生端下载解密后可播放；文件存放服务上只有密文（断言文件内容不是合法 MP4）；篡改一个字节，学生端校验失败并丢弃；下载中断后重试成功。
2b. **真机播放矩阵**：iPhone Safari、华为浏览器、安卓 Chrome、微信内置浏览器，各录一段、互相播放，结果写进 PR（发起人的 Mate 40 Pro 可用作华为一项）。
3. 学生录一段练习发给老师；老师端并排同步播放原视频和新视频；老师回一句话，学生收到。
4. 学生连续 2 天未打卡：第三天镜子页出现提醒；老师端“今天”页把他排在前面。
4b. 每段视频的密钥只发给这一位学生；界面上没有“转发给其他学生”或“存入动作库”的入口。
4c. 老师布置一条“拖地时”的作业：不产生钟点提醒，镜子页出现在“今天做这些事的时候”一栏，可打卡并计入坚持率。
5. 试点指标 CSV 多出“作业坚持率”一列，仍不含任何身份或内容。
