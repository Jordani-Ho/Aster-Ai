# M1-16 内测部署：放在发起人家里的一台电脑上

- 状态：已派（DeepSeek，2026-10-17）
- 依赖：M1-05、M1-07、M1-08（均已完成）
- 决策：发起人 2026-10-17 定，内测阶段服务器放在家里；正式落地（地区、主体、合规）等客户端定型后再决定。

## 目标

一条命令把中继、模型网关（含推送）和手机网页应用在一台家用电脑上跑起来，并让师生的手机在外网用 HTTPS 访问到。**家里路由器不开任何端口。**

## 范围

要做的：`deploy/home/`
1. `compose.yaml`：三个服务
   - `relay`：沿用 `relay/Dockerfile`（两个补丁已在里面）；
   - `gateway`：`gateway/`，环境变量读模型 API 密钥和 VAPID 密钥；
   - `web`：构建 `app/` 后用一个静态文件服务器提供（例如 Caddy，只做静态服务，不负责证书）。
   - 全部关闭访问日志（与 `relay/README.md` 的要求一致）。
2. **外网访问用 Cloudflare Tunnel**（`cloudflared` 容器）：家里电脑主动连出去，不需要公网 IP，不开路由器端口，自动 HTTPS。三个子域名：`app.`、`relay.`、`gw.`（域名由发起人提供，写进 `.env`）。
   - 写清楚备选：没有域名时用 Cloudflare 的临时地址（`trycloudflare.com`）先跑通，但每次重启地址会变，只适合自测。
3. `.env.example`：列出所有要填的值，说明每个值从哪里来；真实 `.env` 不进仓库。
4. `setup.sh`：生成 VAPID 密钥、用 `relay/configure.mjs` 按成员公钥生成中继配置、检查 Docker 是否安装。Windows 用户在 WSL2 里运行。
5. `README.md`：面向发起人的中文操作手册，从“装 Docker”开始，一步一步写，每步说明预期看到什么。包括：怎样添加新成员公钥、怎样重启、怎样备份中继数据目录、怎样停用。
6. **数据只在这台电脑上**：中继数据库目录、订阅文件放在 `deploy/home/data/`，加进 `.gitignore`。

不做的：云服务器、正式域名备案、监控告警。

## 验收用例

1. 在一台干净的 Linux（或 WSL2）上，按 README 从头做一遍能跑起来（在 PR 里贴每步的输出摘要）。
2. 用手机（或 Playwright 模拟手机）经 Tunnel 地址打开应用，能连上中继、调用网关。
3. 非成员公钥连不上中继（沿用 M1-05 的探测）。
4. `docker compose logs` 里看不到任何请求内容、公钥全文或 IP。
5. 重启电脑后 `docker compose up -d` 恢复，数据还在。
