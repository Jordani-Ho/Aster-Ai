# M1-05 中继连接与端到端加密消息

- 状态：待领
- 依赖：M1-01
- 白皮书依据：§3、§4.1、参数表 P8

## 目标

两个节点（学生和老师）能通过中继互发端到端加密的消息。中继只能看到密文，看不出谁发给谁、说了什么。

## 范围

要做的：
- `app/src/core/transport/`：
  - 连接一个或多个中继，断线自动重连；
  - 发送和接收私信：采用 Nostr 的私信规范（NIP-17 私信、NIP-44 加密、NIP-59 礼物包裹）；
  - 中继鉴权（NIP-42）：只有社区成员的公钥可以读写；
  - 每条消息带过期时间（NIP-40），默认 30 天；
  - 统一的应用信封：`{ type, version, payload }`。`type` 先定义 `ping`，后续由各业务卡增加，例如 `consult.package`、`record.signed`、`ledger.event`。
- `relay/`：
  - 评估两款开源中继（例如 strfry、nostr-rs-relay），在 README 里写清选择和理由；
  - 提供本地开发用的启动方式（docker compose），开启鉴权和成员白名单，单条消息上限设为 2 MB，以容纳压缩后的照片；
  - 测试中可以用内存版的模拟中继，不依赖网络。

不做的：
- 推送提醒（M1-08）；
- 具体业务消息的格式（由各业务卡定义）。

## 注意

NIP 编号以 Nostr 官方仓库的当前版本为准，施工前先核对。**不得自造加密格式。**

## 验收用例

1. 学生节点发 `ping` 给老师节点，老师节点收到并解密，内容一致。
2. 直接查看中继里存储的事件：看不到明文，也看不到真实的收件人公钥（礼物包裹生效）。
3. 非成员公钥连接中继时被拒绝读写。
4. 断开网络 30 秒后恢复，期间发送的消息在恢复后送达，且不重复。
5. 过期时间已到的消息不再被中继返回。
6. 发给第三个节点的消息，老师节点无法解密。
