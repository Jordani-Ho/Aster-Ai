# 老师门面：从邀请链接走进老师的馆

状态：方案草案，待发起人与 Claude 审阅；不是已实现功能，也不是编码卡。

作者：Codex｜日期：2026-10-18

`docs/proposals/` 用来放待讨论的产品方案，每份独立成文。本文只说明老师门面的结构、样子和修改边界，不规定代码、接口、存储格式或部署方式。

依据：[第二版结构图·三层分工](../product/v2-structure.md)、[两个智能体、七页界面](../product/two-agents.md)、[发起人决策记录](../../team/decisions.md) 2026-10-18 各条。旧文件中关于加密、原图保留、康币与钱混账的描述不带入本方案；以第二版最新决策为准。

## 1. 门面要让学生认出谁

学生收到阿慈老师的邀请，打开看见“阿慈养生馆”；收到小黄老师的邀请，看见“小黄运动馆”。第一眼回答三件事：这是哪位老师的馆、这里一起做什么、接下来怎么用。

馆名是老师的门牌，不是另建一套账户或一套软件。同一套底层零件可以长成不同的馆；学生始终使用自己的智能体，老师也始终是可核实的同一个人。改馆名不会换老师、重新入门或另开钱账。

不设统一平台首页、老师排行、公开搜馆或商城入口。邀请页不陈列学生名单、健康记录、余额或评价。馆名和介绍不能被包装成平台认证、疗效证明或替代就医的承诺。

## 2. 三层各管什么

| 层 | 我们提供什么 | 门面中的表现 |
| :-- | :-- | :-- |
| 底层 | 身份与邀请核验、天时、抽象器、传递、两本账、观察，以及标题、卡片、按钮等界面零件 | 老师是谁、消息发给谁、记录属于谁、钱怎么记、哪些提醒必须出现，始终可靠 |
| 智能体架构 | 老师智能体与学生智能体的职责、可调整范围、修改后的检查与恢复能力 | 老师智能体替老师打理门面；学生智能体照顾本人习惯；双方都只能调整获准的配置 |
| 表层 | 由各自智能体调整的馆名、标志、配色、介绍、语气、卡片次序等配置 | 阿慈的馆温和安静，小黄的馆清爽直接；我们不为每位老师定制代码 |

我们维护可组合的零件与边界。智能体选用零件、修改配置，不自行生成或改动程序，也不能借一段话术越过底层规则。

## 3. 学生打开邀请链接时

### 第一次来：先认门，再继续现有接入

以下均为虚构示例。手机纵向页面，馆名和老师称呼在首屏；一段短介绍，一个主要行动。说明放在按钮附近，不用一长页条款挡路。

```text
┌──────────────────────────┐
│ [简洁叶形标志]            │
│ 阿慈养生馆                │
│ 阿慈老师邀请你            │
│                          │
│ 一起照顾日常作息，        │
│ 慢慢练成适合自己的习惯。  │
│                          │
│ 从每天照镜子开始；        │
│ 不舒服时，整理后发给老师。│
│                          │
│       [开始使用]          │
│ 接下来接入你自己的模型，  │
│ 由你的智能体陪你记录。    │
│                          │
│ 这里帮助日常调养，        │
│ 不替代医院诊疗。          │
└──────────────────────────┘
```

配色建议：阿慈用暖白背景、深绿主色，少装饰；小黄用浅灰背景、深蓝主色，卡片更利落。都是普通文字和清晰按钮，不靠大幅宣传图铺满首屏。没有标志也能用，馆名就是门牌。

邀请核验在后台完成，不让学生抄身份信息。尚未核实来源时，不把链接里自称的馆名当成已核实老师；核验失败或邀请过期，不显示可入门的确认状态，提示“邀请暂不可用，请向老师要一个新链接”。不因门面漂亮而放宽身份要求。

门面不新增注册表、身份口令、付费关卡或模型接入步骤。新学生仍按现有规则接入自己的模型；已接入者直接继续。新加入的学生进入镜子页，老师门牌留在页首，欢迎内容只占一小块。

### 已经在用：打开就办事

老学生再打开同一位老师的有效邀请，不重复开账户、不重复建关系，也不重复展示入门流程；回到该老师的使用情境。学生尚未完成的模型接入继续完成，已有的个人记录仍归本人。

```text
┌──────────────────────────┐
│ 阿慈养生馆 · 阿慈老师     │
│ 正在记录：本人 ▾         │
│                          │
│ 今天 · 当地天时与天气     │
│ 今日调养要点              │
│ [照镜子]                 │
│ 今天的练习与完成情况      │
│                          │
│   镜子    问诊    其他    │
└──────────────────────────┘
```

馆的门牌持续可见，正文优先给当天要做的事。时辰与钟点可并列或择一显示，沿用天时规则和个人偏好。家人切换显示“正在记录谁”，不能只靠头像或颜色区分。

“问诊”里清楚写“发给阿慈老师”；“其他”里的钱账写明“在阿慈老师这里的余额”和币种。等待老师签字的内容始终标为草稿，不能用品牌话术改成“老师已确认”。无已签方案时，显示通用日常建议，不冒充老师给过个别指导。

## 4. 老师自己能改什么

老师在“管理”中看到一个“我的门面”入口，主要是当前手机效果预览和一句话输入：“想改哪里？”也允许直接点选馆名、颜色和介绍，模型不可用时仍能改这些简单项。

| 项目 | 老师可改的部分 | 保持清楚的边界 |
| :-- | :-- | :-- |
| 名字与标志 | 馆名、日常显示称呼、简单标志 | 显示名不改变老师身份；同名不代表同一人，不提供虚构认证标识 |
| 颜色与外观 | 主色、背景、现成卡片样式、舒展或紧凑的排布 | 正文可读、按钮可辨，急症与草稿等状态不被主题色遮没 |
| 介绍 | 自己的调养方向、日常理念、欢迎语 | 这是老师自述，不变成系统背书或个体诊断 |
| 日常话术 | 更温和或更直接、长短、称呼、欢迎与普通提醒的表达 | 不冒充真人即时回复；不改变急症提示和操作的真实含义 |
| 页面安排 | 现成内容块的显示次序、次要内容折叠、入口旁的解释 | 镜子、问诊、其他仍可找到；收件人、当前本人或家人不能藏掉 |
| 模板与提醒 | 在既有能力内调整问诊表达、作业呈现、普通提醒方式 | 个别调养方案仍须老师本人签字，门面修改不能直接改医嘱 |

例如老师说：“馆名改成小黄运动馆，用蓝色，开头别太客气，提醒短一点。”智能体把这些变成一份门面配置，展示改后的手机样子。老师点“用这个样子”生效，也可以说“只改名字，其他还原”。保留“恢复上次样子”，不设计装修模板市场或多级审批。

老师只说“看起来太冷了”，智能体可以提出暖一点的预览；日常小调整不应每次都变成一轮设置问答。对外的馆名、介绍和整馆主题变化先给老师看，再应用；学生个人的排布与字号偏好不需要老师逐项批准。这是本方案建议的交互，待审阅后再拆卡。

门面保存与问诊签字是两种动作。“用这个样子”不等于给任何健康内容签字，也不会给学生记一笔钱。

## 5. 老师和智能体都改不了什么

| 固定边界 | 门面必须怎样表现 |
| :-- | :-- |
| 就医提醒不可关闭 | 问诊页顶端常驻一句就医提醒，不拦截发送；不判断急症和心理状况，不显示心理援助热线。不能改成营销文案 |
| 签字只能老师本人触发 | 智能体只起草；主题、语气和模板不能代签，不能把草稿装成已签方案 |
| 他人不能冒充老师 | 邀请、消息与签名的归属以真实身份关系为准，不以馆名或标志为准；换手机沿用师生互认规则 |
| 康币属于社区规则 | 老师不能填权重、改比例、发行或扣减康币；当前生产规则数值仍全部 null，界面不显示康币余额 |
| 钱与康币分账 | 老师可以照常定价和确认钱账，但不能用门面把钱改称康币或建立兑换；家庭仍沿用一家一本钱账 |
| 隐私与资料归属 | 门面只介绍老师，不带学生资料；不借装修改变抽象与原图处理规则、不复制其他老师的记录、不承诺新的集中保管方式 |
| 数据保留的既有规则 | 老师仍在专门设置中决定保留期限；门面配色或话术不能暗改期限，也不能承诺永久保存所有记录 |
| 状态与操作含义真实 | 未发送、等待同步、草稿、已签、钱账币种等事实不能隐藏或改成相反含义；不凭馆名生成资质和疗效保证 |

表中的边界沿用已有决策，不是本方案新增治理规则。老师设置的记录保留期限和价格仍由老师决定；它们属于实际业务设置，不混进“换个样子”的动作里。

## 6. 两位老师与学生自己的空间

一个学生可以跟随多位老师，但只有自己的一个智能体。进入“阿慈养生馆”不会抹掉与“小黄运动馆”的关系，也不会把两位老师的方案、记录或钱账混在一起。

建议在“其他 → 我的老师”中切换馆；不用每次启动先选老师。当前馆的名称、问诊收件人、方案来源和钱账归属一一对应，切换时一起切换。本人镜子中的共同记录仍属于本人；跨馆展示或发送内容沿用原有归属与发送规则，切换门面本身不构成授权。

老师决定自己的门牌和内容来源，学生智能体决定本人设备上的可读性与使用习惯。学生可以放大字、收起介绍、调整普通提醒，不因此修改老师对其他学生的门面；老师也不能覆盖学生的字号偏好、其他老师的馆或本人已有记录。

## 7. 改过门面后，以及暂时取不到时

老师改名、换色后，学生在下次能同步时看到新样子；身份、既有关系、已签记录与钱账仍是原来的。旧记录保留当时的签署归属，不因改名而重签。邀请展示的门面始终要与同一老师身份对应；具体怎样分发、更新和缓存由 Claude 另行设计，本文不规定协议。

已入门学生断网时使用上次可信门面并继续本机可做的事；未取到新装饰就先用简洁样式，不阻断已有记录。首次邀请若还没完成核验，不显示“已经加入”或错用另一位老师的缓存门牌。过期邀请不能只靠旧门面继续入门。

调整门面的模型任务暂时失败时，保留已做的草稿；资源恢复后自动续做预览，不自动替老师应用尚未选用的对外变化。普通欢迎语失败不影响本地急症提示，不补发过时提醒。

## 8. 审阅时可以照着走的场景

1. 新学生点阿慈邀请：首屏看到馆名、老师称呼、短介绍与一个主要按钮；接入完成进入镜子，过程中没有身份术语或新增注册表。
2. 相同底层换成小黄邀请：名字、标志、颜色、介绍和语气不同；急症、签字、身份与两本账的规则相同。
3. 老师一句话改名换色：先看到学生视角预览，选用后更新门面；可以恢复，既有医嘱和账目不变。
4. 要求“去掉急症提示”“让智能体替我签字”“充钱送康币”：对应规则不变，智能体用一句话说明边界，继续完成同一请求中允许的外观调整。
5. 学生切换老师或家人：当前老师与记录对象明确，问诊、方案和钱账不串；字号与个人记录不被门面覆盖。
6. 改馆名、断网、模型失败、邀请过期：不重复建关系、不假装成功、不显示错误老师；恢复后续做有效任务。

这些是方案的走查场景，还不是已通过的产品验收。

## 9. 本份方案的范围与待审建议

第一步建议只做门牌、现成主题、短介绍、普通话术和学生视角预览，沿用邀请与现有七页入口；卡片重排、模板和提醒的更细调整留给“自我调整”方案。没有自定义网页脚本、独立域名、支付入口、公开获客页、评价展示或完整装修编辑器。

需要审阅的产品建议有三项：邀请首屏的内容次序；对外门面修改采用“预览 → 用这个样子 → 可恢复”；多老师从“我的老师”切换、默认回到当前使用的馆。这些不是已拍板决策，不据此改动产品代码。认可后由 Claude 决定任务边界并给 DeepSeek 写编码卡。
