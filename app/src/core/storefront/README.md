# 老师门面（V2-09）

一份**只有外观**的门面配置：馆名、显示称呼、标志、主题、短介绍（≤120 字）、欢迎语（≤40 字）。
配置是数据不是代码，老师本人签名，学生只认签名身份，不认馆名。

## 文件

- `index.ts`：配置结构/限长、签名事件（kind 2733）、验签、学生端缓存（按老师公钥、只收更新的版本）、
  老师端当前版与上一版、发布/恢复、`storefront.update` 信封与下发、邀请首屏判定。
- `invite.ts`：把签名门面事件放进邀请链接（`?storefront=<base64url>`，长度上限 3000），
  以及按邀请里的老师公钥验门面。邀请事件与网关格式不变。
- `active.ts`：学生当前在用的馆（`settings/active-teacher`）、门牌文字、钱账按当前馆过滤。
- V2-34：门面签名事件可带老师城市；老师另改城市时用端到端信封发给已登记学生，学生缓存只接受白名单老师的更新。
- V2-35：签名事件附带排班是否已保存，供学生决定是否显示“请求时段”。老师保存排班后重新签发并通知学生；旧门面未带此字段时沿用旧显示。
- `instruction.ts`：老师一句话改门面。先认常见说法（改名/换色/换标志/改介绍/欢迎语），
  认不出且接入了模型时，让模型只回六项配置 JSON；模型失败保留原草稿，不改配置。

## 边界

- 门面配置里只有这六项，没有急症、草稿/已签状态、钱账币种等字段；“用这个样子”不签健康内容、不记钱。
- V2-27 在签名门面事件外层附带老师基础工作里的 `revisitDays`（1–3650 天）供学生本机判断复诊；不改变六项外观配置。旧事件没有此字段时学生不猜默认值。老师修改邀约间隔后，重新签名并发给已有学生。
- 馆名相同不代表同一老师：学生端只显示“我的老师”名单里某位老师本人签名的最新一版；
  时间更旧或同时间的版本不覆盖已缓存的有效版。
- 邀请首屏只在“有效邀请 + 本机还没有这位老师”时出现；老学生打开同一老师邀请直接回原情境。
- 学生端缓存是普通 IndexedDB 数据，断网时用上次收到的那一版；没有门面就用简洁默认样式。
- 老师端只保留当前版与上一版（“恢复上次样子”）；恢复 = 把上一版重新签名成更新的时间。
