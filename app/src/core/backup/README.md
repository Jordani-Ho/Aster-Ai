# 加密备份（M1-06）

复用LocalStore.exportEncrypted/importEncrypted和已批准nostr-tools@2.25.2的NIP-44 v2，不自造加密。中继kind30078事件内容是对完整导出对象再做一次本人到本人的NIP-44加密，连集合名和随机键结构都不裸露。外层作者为备份本人，NIP-42必须与作者相同。

三个固定d槽位aster.backup.0/1/2循环替换最旧快照，NIP-01地址事件语义保留每槽最新一份。并发设备可能覆盖同槽，不提供合并；会话内串行操作。多中继同槽取时间最新/同时间id最小；上传要求所有配置中继确认，任一个失败都显示失败，下次打开重试。

ensureDaily默认开启：每次打开、恢复前台、打开期间每小时检查本地日历日；同日成功不重复，失败仍重试。浏览器关闭期间不能运行定时备份，恢复打开补做。空库先查询中继，有旧快照先恢复，不上传空快照；仅含照片也算非空。没有配置或中继不可达时明确显示失败，不假称已备份。

中继备份用exportEncrypted()排除所有二进制；上限为最终事件2MiB，超出明确失败并提示导出文件。文件用includeBinary:true，包含照片；文件本身也用NIP-44封装，只有相同身份可解密。64MiB文件导入上限防止移动端误加载过大文件；超出可在容量足够设备处理。私钥由助记词重建，不存进文件。

restoreLatest按时间从新到旧逐份解密、校验并尝试原子导入，损坏快照跳过；全部失败才报错且保留原数据。成功后状态时间指向实际恢复的那份。restoreFile在完整认证导入前不修改本地。已有本地记录默认拒绝覆盖，UI要求用户明确勾选替换，并提示先导出照片。中继恢复不含照片；从文件恢复照片。恢复会替换整个业务库。每月提示生成包含照片的文件，界面只声称“已生成”，不声称用户已保存成功。

部署设置VITE_COMMUNITY_RELAYS为逗号分隔的WSS列表（本地允许localhost的ws）；这是公开社区配置。用户也可在备份设置保存地址，保存于本机加密backup-config。清缓存后需使用仍配置社区中继的同一应用，或重新输入地址；助记词本身不含中继地址。

backup-status集合保存结果、尝试/成功/恢复/文件生成时间与固定错误文案；backup-config保存relays。键随机UUID，两者均经M1-02加密。备份会包含这些结构化记录，但空库判定忽略它们。默认未配置中继时会报告，文件功能仍可用。

服务端扩展见relay/backup.md；已rebase到包含PR #16的main，Dockerfile自动应用两个策略补丁，配置生成器自动放行30078。独立小型NIP-01/42适配器只负责备份列出/发布，不做私信。未接真实容器，未证明物理磁盘仅保留三份，未测试真实手机后台行为。

M1-15b：中继备份明确排除 `pilot-metrics`（本机指标不上传，即使加密也不上传）；本机加密文件备份仍可包含指标。恢复可能替换本机指标，导出CSV可自行保留。真实编译中继的30078恢复验收见 e2e/flow.spec.ts，不代表生产容器或手机已验证。

M1-17：恢复词 `recovery-words` 同时从中继与本机业务文件备份中排除，避免隐式上传身份恢复材料；高级恢复先还原身份，再恢复原业务备份。可选刷脸单独把PRF包装身份存到30078的 `aster.identity`，不会开放 `aster.backup.0..2` 或消息读取。启用时先完成备份后再切换本机保护。旧中继不支持新槽时增强启用失败，基础功能保留。

M1-21：BackupStatus 新增可选 modelTestedAt，记录快照生成前读取到的接入版本，不含凭证。ensureDaily 只有当天成功且已覆盖当前接入版本时才跳过；更换或首次保存模型后触发 aster:model-changed，现有 BackupSettings 串行复查并生成快照。备份运行中收到变更会排队复查；网络失败不阻止本机使用。凭据始终作为 settings 加密记录进入备份。
