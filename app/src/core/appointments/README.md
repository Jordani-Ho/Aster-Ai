# core/appointments · 预约

预约由本机 `appointments` 集合保存；中继只传现有 NIP-17 端到端加密信封。`createAppointmentInbox()` 校验方向和已认定的师生关系，按 `offerId` 幂等收消息。邀约固定两小时过期，状态只按任务卡允许的方向变化。容量按老师本地时区的真实时刻计算。

- 新邀约与排班校验都用 `core/schedule/appointments.ts` 的 `appointmentSlots()` 算可约时段。
- 学生通过 `replyToAppointment()` 接受或拒绝；老师确认容量后回确认。多发的一位若也接受，会收到“约满”并获得同一活动中的下一可约时段。
- 老师可在“今天”页记录已到或未到；排班保存前用 `appointmentsAffectedBySchedule()` 列出受影响的预约，可选择保留或取消并通知学生。取消通知先等待中继确认，发送失败时不在本机标成已取消。
- 学生可主动提交最多三个偏好时段，老师端按排班与剩余容量自动确认第一个可约时段；没有可约时段时收到约满或不可约提示。已有未来预约时不重复申请。
- 预约携带老师基础信息中的城市；学生端显示老师邀约时间，并把老师城市作为主要标识、IANA 时区作为补充。
- 老师在开馆基础工作中选择自动邀约或过目后发；复核模式离线时仍能保存本地草稿。
- V2-35：只有老师明确保存过排班，才生成或发送面诊邀约；签名门面将可约状态带给学生，未排班时学生端隐藏“请求时段”，请求路径也再次校验。旧门面未带此字段时沿用旧行为。
- V2-34：老师自动候选和发送时、学生请求时都重验同城；缺少一方城市按同城。已确认预约随排班冲突重算当前城市，学生改为异地后自行决定保留或通知取消。
- V2-36：请出名单后，新邀约候选与活动队列都跳过该学生；已确认预约仍留在两端，照常完成。
- 不接模型、没有中心预约库；离线状态留在本机，连上中继后由现有传输队列发送。
