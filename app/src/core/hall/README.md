# core/hall · 建馆

V2-15：老师第一次进来一步一步开馆。这个目录只放本机状态与第一位邀请的纯逻辑：

- `settings/hall`：`{openedAt, completedAt}`。开馆是本机状态 + 门面签发，不新增服务器接口。
- `settings/opening-guide`：`{step, firstInvite}`。引导走到哪一步、第一张邀请链接与到期时间；关掉应用再打开从同一屏继续。
- `hasOpenedHall`：老部署升级判定——已有门面、学生、病历或收到过问诊，直接视为已开馆，不重走引导。
- `createFirstInvite`：第一位学生的邀请沿用现有签名邀请格式，1 小时只是 `makeInvite` 的有效期参数；链接里仍带老师本人签名的门面。
- V2-26：老师基础模板中的“接收录音”偏好默认开启，与门面事件一起签名发布；旧门面没有该选项时按开启兼容。关闭后学生端不显示录音按钮，并且发送路径再次读取已验签的老师偏好，确保录音引用与字节都不进问诊包。

界面在 `app/src/OpeningGuide.tsx`；管理分块在 `app/src/TeacherManagement.tsx`（V2-16 起整体放在老师端“我的馆”标签里）。

## V2-22 基础工作

`groundwork.ts` 保存 `settings/hall-groundwork`：老师 IANA 时区、时长（15/30/45/60）、容量（1–20）、周一到周日时段、日期例外；邀约方式与间隔天数；不备药/待建库/已建库；六项确认记录。默认周一至周五 9–12、14–17，30 分钟、3 位；邀约默认 review、14 天。日期例外保留历史但只在目标日期不早于老师“今天”时参与计算；`effectivePeriods` 接收老师时区的两个日历日期，不把设备时区当老师时区，也不在本卡解析真实预约时刻。

保存前逐项校验、保存完成才推进到下一未完成项；下次打开依保存记录续做。`groundworkStatus` 还核对四类真实生效模板、已测试的模型与保留期限，不只相信 checked。药材待建库不算完成，库存功能由 V2-24 接入；本卡可先选“不备药”。

新引导在馆名之后、开馆邀请之前显示 HallGroundwork。六项确认不全时开馆及邀请不可用；生成邀请前再次核对。旧部署没有本卡确认记录、但已有 hall 或门面设置时沿用旧邀请流程，首页显示补齐提示，避免强行重走；开始补齐保存后以真实基础工作状态核对。没有任何旧标记的新身份不能借缺省值生成邀请。不做数据迁移。

设置页、首页和我的馆都有同一基础工作入口。模型和保留期限沿用既有接入与 V2-05，不另存第二份。agent/role 读新模板的生效部分与这里的邀约方式；旧设置只作未配置新版时的只读兼容。当前只是准备角色材料，不实际执行排班邀约或库存任务。
