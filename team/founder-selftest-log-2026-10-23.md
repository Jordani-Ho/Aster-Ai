## 二、舌象两个问题的排查

> 只读排查，不改代码。用合成图 + 模拟华为 Mate 40 Pro（Playwright：412×915 / 448×924 CSS、DPR 3、华为浏览器 UA）复现，未使用任何真人照片。
> 代码基线：main f057a0f；证据目录 D:\tmp\tongue-probe\out\；脚本 D:\tmp\tongue-main\run-probe.mjs 等。

### 问题 A：照镜子里的裁剪图只截了一半

**结论：不是拍摄、不是裁剪算法，是照镜子卡片的 CSS 把完整裁剪图又裁了一次。**

- 现网裁剪图本身是完整的（合成图实测 crop 480×416，整条舌头与标记都在）。
- app/src/newui.css:138-139：
  - .nl-mirror-frame { height: 80px; overflow: hidden; }
  - .nl-mirror-frame img { width: 100%; height: 80px; object-fit: cover; }
- 卡片在 app/src/StudentToday.tsx:188-197 直接把 crop 放进这个 img；object-fit: cover 会等比放大后裁掉上下，只剩中间一条。
- 实测可见高度比例：375 宽 → 64%；412（发起人常见视口）→ 55–57%；448（Mate 40 Pro 1344/3）→ **50–51%**。**必现**。
- 该规则由 V2-16 新界面第一批（df8ead3，2026-10-22）引入；同一张 crop 在 TonguePair 里用 object-fit: contain（app/src/tongue.css:4-8）显示是完整的。
- 排除：bbox 归一化、canvas/DPR、EXIF 方向、存储二次缩放都实测不是原因（各图种裁剪尺寸与框一致；EXIF 6/8 下 Chromium 145 默认按方向摆正，若忽略方向会旋转/错位而不是中间一条）。
- 为什么 CI 没抓到：e2e/abstractor.browser.mjs:22-27 只断言 .nl-mirror-frame svg 数量与上次记录，没断言这个 img 的可见比例。
- 证据：out/comparison-crop-vs-mirror.png（完整 crop / 现在 cover / contain 对比）、out/mirror-412-portrait.png、out/deployed-mirror-cover.png、out/report.json 的 mirror.*。

### 问题 B：拍摄反复提示「这次没看清」

**先要分清两句文案（对应不同代码分支）：**

| 屏幕文案 | 代码分支 | 触发条件 |
| --- | --- | --- |
| **这次没看清，请重新拍一张** | abstractor/index.ts:11 RETAKE | ① MIME 不是精确 image/jpeg、image/png、image/webp（image/jpg、大写、空 type、HEIC 全中）② 模型回复不是纯 JSON（json 代码围栏、带说明、空、HTML、>8192 字符）③ 视觉接口失败（401/402/429/5xx/超时）④ 图片 >10MB |
| **没拍清舌头，请靠近一点重拍。** | domain/tcm/tongue.ts:40 TONGUE_RETAKE | 找不到舌头/noTongue、box 缺失或不是恰好四个键、坐标越界、**面积 <5%**、features 字段不对 |

发起人看到的是**「这次没看清」**，所以根因在 RETAKE 分支（MIME / 模型回复格式 / 视觉接口 / 大小），**不是** 5% 框的问题。按华为手机场景可能性排序：

1. **相册/相机给的 MIME 不规范**：image/jpg、大小写、空 type、HEIC/HEIF → 直接失败，模型根本没被调用（瞬间报错）。
2. **模型回复带围栏或说明**：JSON.parse 失败 → 同一句。
3. **视觉 API 失败**：key/额度/5xx/超时，全部映射成这句；表现为每次都一样快或一样慢。
4. 50MP/HDR 原图 >10MB；或服务商对超大图降采样后看不清。
5. 微信内置浏览器可能不拉相机、相册转码、type 为空。

**顺带发现（若学生实际看到“没拍清舌头”那句时成立）：**
- 解析器只认恰好 x/y/width/height 的 0–1 归一化框，面积 ≥5%；0–1000 坐标、像素坐标、xyxy、中心+宽高、多一个字段全部拒绝。
- **5% 阈值过严**：按 4:3 主摄估算，正常 20–40cm 持机距离舌头只占 0.6–2.6%，要到约 14cm 才过 5%（out/framing-table.json）。
- 提示词还写了“不足 5% 就返回 no_tongue”，模型与解析器双重执行同一阈值。
- 失败即清原图、没有自动重试，所以“反复”。
- 舌头路径**没有接** processPhoto（不压图、不去 EXIF），送模型的是原图，大图更吃亏。

### Mate 40 Pro 参数下必现/偶现

| 现象 | 参数 | 必现/偶现 |
| --- | --- | --- |
| 镜子只截一半 | 375/412/448 CSS 宽 | **必现**（约 50–64% 可见） |
| 5% 框拒绝 | 20–40cm 正常距离 | **必现**（约 14cm 才可能过） |
| 框格式拒绝 | 0–1000/像素/xyxy/中心+宽高/多字段 | 取决于模型，同模型下必现 |
| 这次没看清 | MIME 不规范 / HEIC / 模型回复带围栏 / API 401·402·429·5xx / >10MB | 与设置、模型、账户状态相关；触发时必现 |

### 环境因素（与代码无关）
- 华为相机可设 HEIF/HEIC；相册 provider 常给 image/jpg、空 type、大写。
- 微信/内置 WebView 会转码或不拉相机，行为与系统浏览器不同。
- 50MP/HDR/夜景大图会被服务商降采样。
- 真机 EXIF 方向与 Chromium 99 内核行为本机无法验证，需真机一次对照。

### 建议（未改代码）
1. 镜子：.nl-mirror-frame img 改 object-fit: contain（或去掉 80px 固定高），一行 CSS 修好半截。
2. RETAKE 文案分档：图片格式 / 模型回复格式 / 网络或账户 / 图片太大，别让用户瞎重拍。
3. 输入容错：接受 image/jpg、大小写、参数化 MIME；HEIC 给明确提示。
4. 解析容错：去掉 json 围栏再 parse；box 允许统一归一化（B 类，需定口径）。
5. 5% 口径改为占中央/人脸区域比例，或先裁中央再送模型。
6. 送模型前接 processPhoto（≤1600 长边、规范成 jpeg、去 EXIF）。
7. 拍照页加构图提示；失败时能区分原因。
8. 失败只记录错误类别（不含照片），便于后续定位。
