# 老师节点的密文文件服务

使用现有 Node / nostr-tools，不新增服务器依赖。实现 Blossom BUD-01/02/11 的子集：
`PUT /upload`、`HEAD /upload`、`GET|HEAD /<sha256>`。外部入口统一为应用源 `/media/`。
不支持公开下载、列表、镜像、服务端转码、管理页或删除其他人的文件。

所有请求要求 kind 24242 的真实签名，绑定 server（外部域名）、动作、文件哈希及短期过期时间。
每次读取现有成员名单；家人账户经代管人的成员身份下载密文，视频内容仍由家人的独立身份收信。
签名是短时、文件范围内的授权，可在期限内重复请求（方便失败重试）。

只接受 application/octet-stream，单文件上限 60 MiB + 16 字节 AES-GCM 标签。
客户端负责 AES-GCM 加密；服务端无法从任意字节证明加密正确，不应把 MIME 当成加密证明。
流式计算 SHA-256、严格限制长度，临时文件校验完、fsync 后才原子改名。最多 4 个并行上传。
目录只存哈希命名的密文，没有解密信息、学生身份、原文件名或访问日志。

按首次完成上传时间保留 30 天，读取、HEAD、重复上传均不续期。GET 当场拒绝过期文件，
启动及每分钟删除过期文件；清理失败下次重试。崩溃遗留的不可下载临时文件一小时后清理。
仅支持单实例、持久本地磁盘；不能多个进程共写一个目录，不要修改文件 mtime。
文件已过期后可重新上传同一密文，作为一次新的存放。老师节点不做永久视频档案。

部署复用 gateway 镜像，独立进程和数据卷；只在 compose 网络暴露，经同一 Cloudflare 隧道访问。
成员目录只读挂载（而非单文件），兼容现有原子换文件的邀请登记。无请求日志，Docker 日志亦关闭。

为符合本项目必须加成员门面、补丁和独立 Deno/LibSQL 原生运行环境。本卡采用任务卡授权的最小实现，
避免维护上游专用分支。此服务不是完整 Blossom 替代品，只承诺上述子集。
